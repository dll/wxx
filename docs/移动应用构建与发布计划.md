# 任务方案 — 鸿蒙 + iOS 移动应用构建与发布（GitHub Actions）

> 状态：待审核 | 版本：v0.1 | 日期：2026-08-14
> 关联：`docs/蔚小芯前端重新部署.md`、`.github/workflows/deploy-frontend.yml`

## 一、背景与目标

**现状**
- Flutter 前端 `frontend/`（wxx_app，v0.0.27）已支持 Web / Android / iOS / Windows / macOS / Linux。
- 现有 CI 仅产出：Web（Cloudflare Pages）、Go 后端、**Android APK**（`deploy-frontend.yml`）。
- 微信小程序为 **WebView 壳**（`frontend/miniprogram/`，加载 `https://wxx-agent.online`）。
- iOS 目录存在但从未构建发布；鸿蒙（HarmonyOS NEXT）无任何工程。

**目标**
在 GitHub Actions 上自动化构建 **iOS** 与 **鸿蒙** 两种移动应用并发布产品，与 Web/Android 版本号同步。

## 二、范围（做 / 不做）

**做**
1. iOS：Flutter 原生构建 `.ipa`（release），签名并上传 TestFlight（凭据可用时）。
2. 鸿蒙：ArkTS **WebView 壳**工程（复用小程序成功模式），`hvigorw` 构建 HAP。
3. 新增独立 workflow（`build-mobile.yml`），不改动现有部署链路。
4. 产物挂 GitHub Release / Actions artifacts，随版本号发布。
5. 更新构建/部署文档并登记 AGENTS.md 索引。

**不做**
- ❌ 不将整个 Flutter 应用移植到鸿蒙（OpenHarmony Flutter fork 插件兼容风险高、违反"勿引入高风险依赖"）。
- ❌ 不引入本地大模型、Docker、Coze（项目红线，仅用官方/云 CI）。
- ❌ 本次不做 iOS 模拟器自动化测试与鸿蒙 UI 测试（后续增量）。

## 三、技术要点

### 3.1 iOS（Flutter 原生）

| 项 | 方案 |
|----|------|
| Runner | `macos-latest`（GitHub 托管 macOS），Xcode + Flutter 3.22.0（与现有 CI 一致） |
| 构建 | `flutter build ipa --release --dart-define=...`（地图 AK 同 Web/APK） |
| 签名 | Apple 开发者：证书 p12 + provisioning profile，或 App Store Connect API Key（.p8）自动签名 |
| 上传 | `xcrun altool` / `appstore-connect` CLI 传 TestFlight |
| Secrets | `APPLE_TEAM_ID`、`APPLE_CERT_BASE64`、`APPLE_CERT_PASSWORD`、`APPLE_PROFILE_BASE64`、`APPLE_ASC_KEY_ID`、`APPLE_ASC_ISSUER_ID`、`APPLE_ASC_PRIVATE_KEY`（均不进仓库） |
| 兜底 | 无凭据时产**未签名 `.ipa`** 制品（Actions artifact 可下载） |

### 3.2 鸿蒙（ArkTS WebView 壳，HarmonyOS NEXT）

| 项 | 方案 |
|----|------|
| 工程 | `frontend/harmonyos/`（新建，AppGallery 标准工程结构：entry 模块） |
| 核心 | ArkTS WebView 组件加载 `https://wxx-agent.online`，与小程序壳同构 |
| 构建 | `ohpm install` + `hvigorw assembleHap`（CI 装 JDK17 + Node + HarmonyOS SDK） |
| SDK | DevEco 命令行工具 + HarmonyOS SDK（官方下载，runner 安装） |
| 签名 | 华为 AGC 签名证书（`.cer` / `.p12` / profile），`signingConfigs` |
| Secrets | `HUAWEI_SIGNING_CERT`、`HUAWEI_SIGNING_P12`、`HUAWEI_SIGNING_PROFILE` |
| 兜底 | 无凭据时产 **debug / 未签名 HAP** 制品（真机需 DevEco 或签名安装） |

> 风险：HarmonyOS SDK 从华为服务器下载在海外 runner 可能慢/受限；必要时用华为镜像源或 `workflow_dispatch` 手动触发。若 GitHub runner 不可行，备选华为云 CodeArts 流水线（独立于本方案，不在本期实现）。

### 3.3 版本与发布策略
- 版本号统一读 `frontend/pubspec.yaml`（与 `build-all.ps1` 一致）。
- 发布：GitHub Release 同名 `vX.Y.Z`（现 APK 已用该 Tag，Release 补充 ipa + hap 资产）。
- 触发：`workflow_dispatch` 手动 + push 至 `main`（可选开关，避免每次提交烧 macOS 分钟数）。

## 四、步骤拆分

1. **iOS 预检**：Info.plist 显示名/版本、Runner 签名设置、bundle id（现 `com.wxx.wxxApp`）。
2. **iOS workflow**：macOS runner → Flutter build ipa → 签名 → 上传 TestFlight（或 artifact 兜底）。
3. **鸿蒙工程**：创建 `frontend/harmonyos/` ArkTS WebView 壳（App 名「蔚小芯」、图标、bundle id）。
4. **鸿蒙 workflow**：装 JDK17/Node/HarmonyOS SDK → `ohpm install` → `hvigorw assembleHap` → 签名 → Release/artifact。
5. **发布**：Release 资产补充 + 触发策略 + 版本同步脚本。
6. **文档**：新增 `docs/移动应用构建与发布.md`，更新 AGENTS.md 文档地图。

## 五、验收标准

- [ ] iOS：CI 产出 `.ipa`；配置凭据后 TestFlight 出现可用 build。
- [ ] 鸿蒙：CI 产出 HAP（debug 可装 HarmonyOS NEXT 真机/模拟器）。
- [ ] 两个产物均挂 GitHub Release 可下载，版本号与 Web/APK 一致。
- [ ] 现有 Web/后端/APK 部署链路不受影响（独立 workflow）。
- [ ] 凭据仅存 GitHub Secrets，仓库无任何敏感信息。

## 六、回滚与检查点

- 新 workflow 独立触发，不影响 `deploy-frontend.yml`；出问题可单独停用。
- 每步增量：Git 提交 + 文档同步（Harness 纪律）。
- 凭据泄露预案：从 Secrets 删除并重新生成签名证书。
