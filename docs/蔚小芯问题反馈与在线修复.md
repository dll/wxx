# 蔚小芯 问题反馈与在线修复

> 版本：v2.0 · 2026-08-12
> 完整闭环：**用户提交 → 可靠入库（不丢数据）→ 管理端处理 → 结构化复制 → AI 工具修复 → 验证 → 标记已解决**。
> 目标：管理员在本机（开发环境）可"边使用、边修复 Bug、边增强功能"。

## 一、整体闭环

```
用户/管理员在任意页面发现问题
        │
        ▼
提交反馈（文字为主，截图佐证）──────── 提交失败 → 本地草稿保留，可重试
        │ 成功入库（含截图 base64 内联）
        ▼
管理端「反馈管理」列表 / 详情
        │
        ├─ 在线修复面板（AI 定位模块 + 代码文件 + 根因 + 建议）
        │        ├─ 复制完整报告（Markdown）
        │        ├─ 复制结构化 JSON
        │        └─ 闭环引导：复制 → AI 修复 → 本地验证 → 标记已解决
        ▼
管理员在本机 / AI 工具中修复代码或知识库
        │
        ▼
本地验证通过（flutter analyze / go test / 页面复现）
        │
        ▼
回面板「验证通过并标记已解决」→ 状态 resolved + 回复用户 + 处理记录
```

## 二、反馈提交（用户端）

- 入口：对话纠错（chat_page）、全局反馈对话框（`widgets/feedback_dialog.dart`）。
- 字段：类型（回答有误/功能建议/其他）、**所属模块**（前端 `feedbackModules` 枚举）、内容（文字主体）、截图（自动截屏，**仅作佐证**）。
- 提交接口：`POST /api/v1/feedback`（能力 `self.feedback.submit`），即时入库。
- 截图：自动截取当前页面帧；Web 端缩放到 960×540 以内、≤900KB，以 base64 data URL 内联存入 `feedback.screenshot_url`，与反馈记录一并入库，**跨实例不丢图**。

### 可靠提交（不丢数据）

- **本地草稿**：输入内容/分类/模块在对话框关闭或提交失败时自动保存到本地（SharedPreferences，`utils/storage.dart` 的 `feedbackDraft*`），下次打开自动恢复。
- **失败重试**：提交失败（网络/500/401）时保留全部输入，仅提示错误，可直接重试；不丢失任何已输入文字。
- 提交成功后清除草稿。

## 三、反馈管理（管理端）

- 入口：我的 → 管理服务 tab →「反馈管理」（`pages/admin/feedback_page.dart`，能力 `union.feedback.list`）。
- 仪表盘：反馈总数 / 待处理 / 处理中 / 已解决 / 近7天趋势 / 热门分类 / 平均解决时长。
- 列表：状态筛选（全部/待处理/处理中/已解决/已驳回）、状态标签、模块标签、行内复制按钮、驳回/处理中/解决操作。
- 详情：基本信息（状态/分类/模块/ID/提交人/时间）、反馈内容（可选中复制）、截图（可放大）、关联知识资源、处理回复、满意度、处理记录时间线。

### 状态流转

| 状态 | 说明 | 触发 |
|------|------|------|
| `pending` | 待处理（提交默认） | 用户提交 |
| `processing` | 处理中 | 管理员标记 |
| `resolved` | 已解决 | 管理员确认修复完成（在线修复面板「标记已解决」或列表「解决」） |
| `dismissed` | 已驳回 | 管理员驳回 |

- 每次状态变更写入 `feedback_logs`（操作人/动作/详情/时间），前端详情页以时间线展示。

## 四、结构化复制（交给 AI 工具修复）

统一报告函数：`utils/feedback_report.dart` 的 `FeedbackReport`，生成 **JSON 与 Markdown 双格式**，三处复用，保证字段完整、不丢数据。

### 覆盖字段（全量）

反馈 ID、用户 ID、用户名、类型及标签、模块、内容、状态及标签、消息 ID、关联资源 ID、截图 URL、提交时间、处理人、处理时间、回复、满意度评分/评论、处理记录列表；附加 AI 诊断（摘要/OCR/根因/修复建议/模块/代码文件/匹配文件）。

### 三处复制入口

| 位置 | 按钮 | 格式 |
|------|------|------|
| 管理端详情右上角 | 复制完整反馈 | Markdown（含处理记录） |
| 在线修复面板 | 复制完整报告（提交 AI 修复） | Markdown（含反馈+AI 诊断+代码文件+修复建议） |
| 在线修复面板 | 复制结构化 JSON | JSON（AI 工具精确解析） |
| 用户端「我的反馈」卡片/详情 | 复制反馈数据 | JSON |

## 五、AI 在线修复（管理端核心）

反馈详情点击「在线修复」→ 底部面板（`widgets/feedback_repair.dart`）→ `POST /api/v1/feedback/:id/ai-repair`（能力 `admin.feedback.write`）。

流程：
1. **截图解析**：复用 `Zhipu4VClient`（GLM-4.6V-Flash）OCR 反馈截图（blob 从 `feedback.screenshot_url` 读取）。
2. **AI 诊断**：文本模型（DeepSeek/智谱 failover）基于「内容 + 模块 + OCR 文本」输出 JSON：模块、摘要、代码文件、根因、修复建议。
3. **降级**：LLM/视觉不可用时，用本地关键词模块映射（`moduleFilesMap`）兜底返回 `matched_files`。
4. 面板展示：问题摘要、截图 OCR、根因分析、相关代码定位、修复建议（关联知识资源时给出可执行修正步骤）。

实现位置：
- 后端：`internal/service/feedback_service.go`（`AIRepair`）、`internal/handler/feedback_handler.go`、路由 `app.go`。
- 前端：`widgets/feedback_repair.dart`、`providers/feedback_provider.dart`（`aiRepair`）。
- 模型配置：`ZHIPU_4V_MODEL`（服务器 `/etc/wxx/env`，现为 `glm-4.6v-flash`）。

## 六、修复闭环（修复 → 验证 → 解决）

在线修复面板内嵌「修复闭环」引导，串起完整流程：

1. **复制**：复制完整报告（Markdown）或结构化 JSON，粘贴给 Claude / GLM 等 AI 工具。
2. **定位**：AI 工具按报告中的模块/代码文件/根因定位问题。
   - 代码 bug → 定位 `code_files` / `matched_files`。
   - 知识库内容错误 → 反馈关联 `resource_id` 时，修正 `kb_resources` 内容并同步迁移源 `server/migrations/*.sql`（防新环境复现）。
3. **修复**：在本机（开发环境）直接修改代码或知识库。
4. **验证**：本地验证通过（`flutter analyze` 0 错误、`go test`、页面复现正常）。
5. **标记已解决**：回面板点击「验证通过并标记已解决」→ 可选回复 → 状态置 `resolved`、记录处理人、通知提交用户、关闭面板。

## 七、实现与验收

### 涉及文件（前端，本次闭环增强）

| 文件 | 作用 |
|------|------|
| `utils/feedback_report.dart` | 统一结构化报告生成（JSON + Markdown） |
| `utils/storage.dart` | 反馈草稿持久化 |
| `widgets/feedback_dialog.dart` | 提交对话框（草稿恢复/保存、失败重试） |
| `widgets/feedback_repair.dart` | 在线修复面板（复制报告/JSON + 闭环引导 + 标记已解决） |
| `pages/admin/feedback_page.dart` | 管理端列表/详情（复制完整反馈） |
| `pages/profile/my_feedbacks_page.dart` | 用户端「我的反馈」复制按钮 |

### 验收标准

- 提交失败/关闭对话框后输入完整保留，下次打开自动恢复，可重试。
- 三处复制由同一函数生成，字段完整（含 ID/内容/状态/截图/资源/记录/AI 诊断）。
- 修复面板支持「复制 → AI 修复 → 验证 → 标记已解决」完整闭环，状态流转有处理记录。
- `flutter analyze` 0 error / 0 warning；`flutter test` 通过；Web 构建成功。
