## 一、项目定位

本项目建设面向油气田业务的综合数字化生产平台，覆盖地质、工程、生产、SCADA 与物联网、一张图、数据及公共管理六大业务域，并提供统一认证、组织权限、流程审批、消息、文件、日志、审计、接口和数据治理等公共能力。

项目不是普通 CRUD 后台，具有以下特点：

- 专业业务域多，涉及地质、钻井、固井、井控、钻井液、压裂、试油和生产调度；
- 同时处理结构化业务数据、实时采集数据、时序曲线、GIS/三维资料、SEG-Y 和大文件；
- 需要与集团平台、供应商、SCADA、GIS、视频、统一认证及 AI 服务集成；
- 对数据标准、质量治理、权限、安全审计、可追溯和分批上线有较高要求。

## 三、用户与权限

主要用户包括平台管理员、地质人员、工程人员、生产管理人员、现场/设备人员、数据管理员、业务审核人、领导/驾驶舱用户、集成运维人员和安全审计人员。

平台采用“用户—组织—角色—数据范围—操作权限”模型：

- 支持按组织、区域、区块、井、设备、项目和资料类别控制数据范围；
- 支持查看、新增、修改、删除、审核、发布、导入、导出和配置权限；
- 外部接口使用独立身份、密钥和接口权限；
- 权限变化、数据变更、审批、导入导出和高风险操作必须审计；
- 关键数据原则上采用版本或归档管理，不允许无痕删除。

## 四、核心业务需求

### 4.1 地质管理

建立井、层位、储层、岩心、物性、录井、测井、地震、图件和三维资料的统一档案。支持专业资料目录、文件与结构化数据关联、曲线查询、图件预览、版本管理、空间定位、地质导向和质量问题闭环。

SEG-Y 专业解析、地震解释、三维渲染、格式转换和商业引擎能力，需以最终技术方案及授权范围为准。

### 4.2 工程管理

覆盖工程项目和单井工程从计划、设计、施工、监督、质量控制到完工归档的过程，重点支持钻井、固井、井控、钻井液、控压钻井、压裂和试油。

关键记录应支持计划/实际对比、异常提示、责任人、整改时限、证据附件、审核和归档，并与地质、生产、设备和供应商对象关联。

### 4.3 生产管理

支持生产计划、调度指令、实际完成、偏差分析、生产预警、处置闭环、实时/历史曲线和统计报表。预警需要支持分级、确认、转派、处置、关闭和复盘。

### 4.4 SCADA 与物联网

平台侧负责约定范围内的数据接收、协议解析、点位管理、映射转换、单位换算、质量码识别、实时监控、历史查询、接入日志和失败补偿；不默认包含现场传感器、PLC、RTU、边缘网关、现场安装和通信网络。

必须在实施前确认协议清单、点位数量、采样周期、峰值吞吐、实时延迟、历史数据量、保留年限、补传机制和网络安全边界。

### 4.5 首页一张图

建设综合驾驶舱和 GIS 一张图，展示地质、工程、生产、物联、数据质量和运营指标。支持地图图层、指标卡片、趋势、告警、待办、区域/区块/井/设备/点位逐级下钻。

每个指标必须明确名称、定义、计算公式、来源、刷新频率、统计周期、权限范围和异常状态。

### 4.6 数据及公共管理

建设数据标准、主数据、字典、质量规则、质量问题、文档资料、需求变更、流程中心、批量导入导出、公共查询和审计能力。

数据治理闭环为：规则配置 → 校验 → 问题登记 → 分派整改 → 复核 → 关闭 → 统计分析。

## 五、建议技术架构要求

技术方案建议采用前后端分离、分层解耦和适配器可替换架构：

```text
Web/移动/驾驶舱
  → API 网关与统一认证
  → 地质/工程/生产/物联/一张图/数据治理业务服务
  → 权限/流程/消息/文件/报表/审计公共服务
  → 关系库/时序库/对象存储/缓存/检索
  → 集团/供应商/SCADA/GIS/视频/AI 集成适配
```

技术要求：

1. 关系型数据库承载主数据和业务事务，时序数据库承载高频采集数据，对象存储承载大文件；
2. 外部系统通过适配层接入，核心业务不直接依赖供应商专有格式；
3. 实时采集与业务事务解耦，接入中断不得阻塞常规业务；
4. 接口统一版本、认证、错误码、超时、重试、幂等、补偿和日志；
5. 页面支持草稿、校验、提交、退回、修订和版本；
6. 支持开发、测试、预生产和生产环境隔离，以及健康检查、日志、监控、告警和发布回退；
7. 具体数据库、中间件、操作系统、GIS/三维引擎和部署方式，以容量、安全和信创要求确认后冻结。

本章属于技术方案要求，不替代后续总体设计和详细设计。

## 六、项目组织与实施计划

### 6.1 建议项目团队

项目高峰期建议配置项目经理、需求/产品经理、技术架构师、地质业务分析师、工程业务分析师、生产/物联分析师、后端开发、前端/GIS/可视化、数据工程、集成、测试、安全运维和培训实施人员。

按总工作量估算，建议平均投入 **7—9 人**，峰值 **12—16 人**。甲方应同步配置业务专家、数据负责人、接口负责人、信息化负责人和验收组。

### 6.2 建议工期

整体工期 **12—15 个月**，可分两批或三批上线：

| 阶段 | 周期 | 主要成果 |
|---|---:|---|
| 项目启动 | 1—2 周 | 项目章程、计划、责任矩阵 |
| 需求澄清 | 4—6 周 | 需求基线、原型、接口和数据问题清单 |
| 总体设计 | 4—6 周 | 总体方案、数据/接口/部署/安全设计 |
| 公共底座 | 8—10 周 | 认证、权限、流程、消息、日志、文件 |
| 第一批业务 | 12—16 周 | L01、L03、L06 核心及基础驾驶舱 |
| 第二批业务 | 16—20 周 | L102、L04、L05 深化及专业联调 |
| 数据与集成 | 10—14 周 | 历史初始化、外部接口、实时/GIS 联调 |
| 试运行验收 | 6—8 周 | 培训、试运行、整改、初验和终验 |

各阶段可并行，但前提是甲方及时提供需求确认、接口环境、样例数据、测试账号和业务专家。

## 八、验收与付款

### 8.1 验收方式

采用“功能点—业务域—平台整体”三级验收：

1. 功能点：按原始 Excel 编号逐项核对功能、权限、输入、输出和异常场景；
2. 业务域：按六大业务域验证端到端流程；
3. 平台整体：验证认证、权限、流程、接口、审计、部署、培训和试运行。

实时接入、GIS/三维、SEG-Y、历史数据、接口、安全和性能应分别制定专项验收条件。性能验收必须在双方确认的生产同构环境、容量基线和测试脚本下执行。

### 8.2 建议付款节点

- 项目启动：20%；
- 总体设计及原型确认：20%；
- 核心业务一期上线：25%；
- 全部功能开发完成并进入试运行：20%；
- 初验：10%；
- 终验/质保金：5%。

付款节点应与确认成果和验收证据绑定。未纳入乙方合同范围的外部系统、现场设备、商业授权和安全测评，不应作为乙方软件付款的无条件前置。

## 九、主要风险与前置条件

1. **原始需求风险：** 需提供原始 Excel 并完成 178 项逐项确认；
2. **实时数据风险：** 需确认协议、点位、频率、容量、质量码和历史策略；
3. **数据初始化风险：** 需提供合法、完整、可读的历史数据和数据字典；
4. **专业组件风险：** 需明确 GIS/三维/SEG-Y 格式、授权、解析和性能范围；
5. **接口风险：** 需明确接口提供方、环境、账号、字段映射和联调窗口；
6. **安全风险：** 需尽早确认等保、密评、工控边界、信创和容灾要求；
7. **范围风险：** 采用需求基线、变更单和 ±15% 需求调整机制；
8. **责任风险：** 通过甲乙方责任矩阵区分设备、网络、边缘层、平台层和第三方服务。
