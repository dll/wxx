# 用户数字画像升级说明

## 一、产品意图

将学生端的数字孪生从“展示成长数据的画像页”渐进升级为“我的头像与成长”体验：先让学生看到一个有趣、可爱、具 AI 感的头像，再把真实成长数据作为可解释的成长详情呈现。头像是表达层，不替代真实数据，也不应制造不存在的能力或结果。

本次升级遵循以下边界：

- **可选**：不上传照片也能使用默认校园数字人头像和全部成长功能。
- **可定制**：学生主动选择照片后，才提交照片数据进行照片版头像生成；也可以选择无照片的校园原型模式。
- **诚实**：只有后端图片生成服务实际可用时才展示生成结果；服务未配置、生成失败或数据未加载时，明确展示状态，不伪造 AI 结果。
- **有趣但克制**：头像视觉可以轻松、Q 版、富有个性；雷达图、综合分和成长阶段仍承担数据解释责任。
- **渐进重构**：复用现有数字孪生、头像卡片和头像生成契约，不重建页面、不改变既有成长数据口径。

## 二、用户体验意图

1. 进入页面后，用户首先获得清晰的头像反馈，而不是先阅读一组分数。
2. 用户能够立即理解：默认头像可直接使用，照片只是可选的个性化入口。
3. 用户能够在默认头像、校园原型头像和照片定制头像之间形成明确认知，不把三者混为同一种数据来源。
4. 用户在等待、空态、错误和服务未配置时，都能获得可行动的提示。
5. 成长数据继续保留在同一页面中，作为“头像背后的成长详情”，避免娱乐化视觉遮蔽真实状态。

## 三、实现范围

### 已实现

- 页面标题与首屏层级调整为“我的头像与成长”。
- 已生成头像优先展示；无生成头像时回退到默认 `AvatarCard`；头像尚未加载时显示占位。
- 增加 `AvatarCustomization` 请求结构，区分 `default` 与 `photo`，仅在照片模式确有内容时提交照片字段。
- 保留校园原型生成入口，并在定制区域明确照片可选和图片生成服务依赖。
- 页面进入和下拉刷新时同步加载头像定制结果。
- 为默认模式和照片字段提交规则增加测试。

### 暂不扩大范围

- 不新增后端接口或图片生成供应商配置。
- 不在本次改动中重写成长数据、雷达图算法或移动端相机适配。
- 不将本地上传照片默认为公开资料；照片提交必须由用户主动触发。

## 四、验收口径

- 无照片用户可以进入页面、看到默认头像并查看成长详情。
- 照片未选择时，请求中不得包含 `photo_base64` 和 `photo_mime`。
- 照片模式有内容时，照片字段和 MIME 类型正确传递。
- 图片生成服务不可用时，页面展示真实错误或未生成状态，不展示伪造图片。
- 页面已有的成长数据、刷新行为和数字孪生接口不被破坏。
- `flutter test test/twin_honest_state_test.dart` 通过，且目标文件 `flutter analyze` 无错误。

## 五、后续演进方向

- 移动端接入原生相机与相册选择，并沿用用户主动授权和主动提交原则。
- 增加头像版本、生成时间、来源类型和删除/换回默认头像的可见状态。
- 在图片生成服务稳定后，再评估风格选择、个性亮点推荐和成长数据驱动的轻量装饰；不得把推断结果包装成事实。
