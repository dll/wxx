# 蔚小芯后端部署文档

## 概述

蔚小芯后端采用 **Cloudflare Pages Functions + Turso 云数据库** 的无服务器架构，实现数据持久化和高可用部署。

**为什么选择这个方案？**
- 原方案（Vercel + Go + SQLite）因 Vercel 无服务器函数的临时文件系统导致 SQLite 数据丢失，冷启动后重置
- 改用 Turso 云数据库解决持久化问题
- 改用 Cloudflare Pages Functions 替代 Vercel Go 函数，与前端同域部署，避免跨域问题
- 全球边缘节点，访问速度快，免费额度充足

## 部署流程

### 自动部署（推荐）

项目已配置 GitHub Actions 自动部署，代码推送到 `main` 分支后自动触发。

**工作流文件**: `.github/workflows/deploy-frontend.yml`

**触发条件**:
- `frontend/` 目录下的文件有变更
- `.github/workflows/deploy-frontend.yml` 有变更
- 手动触发（workflow_dispatch）

**部署步骤**:
1. 检出代码
2. 安装 Flutter 3.38.5
3. 执行 `flutter pub get`
4. 执行 `flutter build web --release`
5. 使用 wrangler 部署到 Cloudflare Pages：
   ```bash
   wrangler pages deploy build/web --project-name wxx-agent --branch main --functions-dir functions
   ```

### 手动部署

```bash
cd frontend

# 构建 Flutter Web
flutter build web --release

# 部署到 Cloudflare Pages（需先登录 wrangler）
npx wrangler pages deploy build/web --project-name wxx-agent --branch main --functions-dir functions
```

## 数据持久化说明

### 问题背景

Vercel 无服务器函数使用临时文件系统，每次冷启动后文件系统重置，导致 SQLite 数据库中的数据丢失。

### 解决方案

采用 **Turso 云数据库** 替代本地 SQLite：

- Turso 是基于 libsql 的分布式 SQLite 云服务
- 100% 兼容 SQLite 语法，迁移成本低
- 免费额度充足（500 个数据库，9 GB 存储）
- 全球边缘节点，低延迟访问

### 双驱动支持

Go 后端代码支持双数据库驱动，通过 `DB_PATH` 环境变量自动切换：

- **本地 SQLite**: `DB_PATH=./data/wxx.db`
- **Turso 云数据库**: `DB_PATH=libsql://xxx.turso.io`

## 常见问题

### Q: 为什么不继续用 Vercel + Go？

A: Vercel Go 部署遇到两个问题：
1. Vercel 无服务器函数的临时文件系统导致 SQLite 数据丢失
2. Go 版本兼容性问题（Vercel 支持到 Go 1.22，项目依赖需要更高版本）

### Q: 为什么用 Cloudflare Pages Functions 而不是 Cloudflare Workers？

A: Pages Functions 与前端静态页面同项目部署，共享域名，无需额外配置跨域，维护更简单。

### Q: 数据安全吗？

A: 
- Turso 数据库支持加密连接
- 密码使用 SHA-256 + 盐值哈希存储
- JWT Token 7 天过期
- 生产环境建议通过 Cloudflare Pages 环境变量管理密钥，不要硬编码

### Q: 如何备份数据库？

A: 使用 Turso CLI：
```bash
turso db shell wxx-agent ".backup backup.sql"
```
