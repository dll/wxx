## 1. 部署架构概览

### 1.1 整体架构

```
┌─────────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│  前端（Flutter） │────▶│  Cloudflare Pages    │────▶│  后端（Go API）  │
│  Web / APK / 小程序│     │  Functions 代理      │     │  Vercel / 自托管 │
└─────────────────┘     └──────────────────────┘     └────────┬────────┘
                                                              │
                                                    ┌─────────▼─────────┐
                                                    │   数据库            │
                                                    │  Turso / SQLite    │
                                                    └───────────────────┘
```

### 1.2 两种部署模式对比

| 特性 | Vercel + Turso | Linux 单机 |
|------|---------------|------------|
| 数据持久化 | Turso 云端 | 本地 SQLite 文件 |
| 冷启动 | 有（无服务器函数） | 无（常驻进程） |
| 运维成本 | 低（免运维） | 中（需维护服务器） |
| FTS5 全文检索 | 支持 | 支持 |
| 数据库连接 | `libsql://` 协议 | 文件路径 |
| 适用场景 | 开发/测试/生产 | 生产环境（大规模） |

### 1.3 数据库驱动自动选择机制

后端通过 `DB_PATH` 环境变量自动选择数据库驱动：

```
DB_PATH=libsql://xxx.turso.io?authToken=xxx  →  Turso 云数据库（libsql-client-go 驱动）
DB_PATH=./data/wxx.db                        →  本地 SQLite 文件（modernc.org/sqlite 驱动）
```

代码位置：`server/pkg/app/app.go` → `initDB()` 函数

## 2. 数据库部署

### 2.1 方式一：Turso 云数据库（Vercel 部署必选）

#### 2.1.1 注册 Turso 账号

1. 访问 https://turso.tech
2. 点击 "Sign Up"，使用 GitHub 或 Google 账号登录
3. 免费额度：500 个数据库，9GB 总存储，10亿次读取/月

#### 2.1.2 创建数据库

**方式 A：网页控制台**

1. 登录 https://turso.tech/app
2. 点击 "New Database"
3. 数据库名称填 `wxx-agent`
4. 选择最近的区域（如 Singapore）
5. 点击 "Create"

**方式 B：Turso CLI**

```bash
# 安装 Turso CLI（macOS/Linux）
curl -sSfL https://get.tur.so/install.sh | bash

# Windows（PowerShell）
irm https://get.tur.so/install.ps1 | iex

# 登录
turso auth login

# 创建数据库
turso db create wxx-agent

# 查看数据库 URL
turso db show wxx-agent --url
# 输出: libsql://wxx-agent-<your-org>.turso.io

# 创建 Auth Token
turso db tokens create wxx-agent
# 输出: eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9...
```

#### 2.1.3 初始化数据库 Schema

```bash
# 设置环境变量
$env:DB_PATH = "libsql://wxx-agent-xxx.turso.io?authToken=eyJhbGci..."

# 执行数据库迁移（创建表 + 插入 44 条种子数据）
cd server
go run cmd/migrate/main.go
```

迁移工具会自动：
- 创建所有数据库表（users、kb_resources、kb_fts、sessions 等）
- 创建 FTS5 全文检索索引
- 插入 44 条知识种子数据
- 插入 10 个内置测试用户

#### 2.1.4 获取连接串

最终用于 Vercel 的 `DB_PATH` 格式：

```
libsql://wxx-agent-xxx.turso.io?authToken=eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9...
```

### 2.2 方式二：本地 SQLite 文件（自托管部署）

#### 2.2.1 数据库文件

本地模式下，SQLite 数据库文件存储在 `./data/wxx.db`，数据自动持久化。

#### 2.2.2 初始化数据库

```bash
# 设置环境变量（默认值为 ./data/wxx.db）
export DB_PATH=./data/wxx.db

# 执行迁移
cd server
go run cmd/migrate/main.go
```

#### 2.2.3 数据库文件备份

```bash
# 备份
cp data/wxx.db data/wxx-backup-$(date +%Y%m%d).db

# 恢复
cp data/wxx-backup-20260101.db data/wxx.db
```

## 3. 后端服务部署

### 3.1 方式一：Vercel 部署（推荐）

#### 3.1.1 前置条件

- 已创建 Turso 数据库并完成 Schema 初始化
- 已安装 Node.js（v18+）和 npm

#### 3.1.2 安装 Vercel CLI

```bash
npm install -g vercel
```

#### 3.1.3 登录 Vercel

```bash
vercel login
# 按提示完成浏览器 OAuth 登录
```

#### 3.1.4 配置环境变量

在 Vercel 项目设置 → Environment Variables 中添加，或使用 CLI：

```bash
# 数据库（Turso）
echo "libsql://wxx-agent-xxx.turso.io?authToken=xxx" | vercel env add DB_PATH production

# JWT
echo "your-jwt-secret-min-32-chars" | vercel env add JWT_SECRET production
echo "2" | vercel env add JWT_EXPIRE_HOURS production

# LLM API Keys
echo "your-zhipu-api-key" | vercel env add ZHIPU_API_KEY production
echo "your-deepseek-api-key" | vercel env add DEEPSEEK_API_KEY production

# 讯飞语音
echo "your-xfyun-app-id" | vercel env add XFYUN_APP_ID production
echo "your-xfyun-api-key" | vercel env add XFYUN_API_KEY production
echo "your-xfyun-api-secret" | vercel env add XFYUN_API_SECRET production

# 应用配置
echo "release" | vercel env add APP_MODE production
echo "https://wxx-agent.pages.dev" | vercel env add CORS_ALLOWED_ORIGINS production
```

#### 3.1.5 部署

```bash
# 在项目根目录执行
vercel --prod --yes
```

部署完成后，后端地址为：`https://wxx-server.vercel.app`

#### 3.1.6 Vercel 项目配置

项目已有 `.vercel/project.json` 配置：

```json
{
  "projectId": "prj_jnYd0sSw7GKji8pbWgxT6OPR55HD",
  "orgId": "team_gea581HPgTeBL8GKn46YwmO3",
  "projectName": "wxx-server",
  "settings": {
    "framework": "go",
    "nodeVersion": "24.x"
  }
}
```

`vercel.json` 配置（所有路由重写到 `/api`）：

```json
{
  "version": 2,
  "rewrites": [
    { "source": "/(.*)", "destination": "/api" }
  ]
}
```

Vercel 入口文件 `api/index.go`：

```go
// Handler Vercel serverless 入口
func Handler(w http.ResponseWriter, r *http.Request) {
    handler.ServeHTTP(w, r)
}
```

### 3.2 方式二：Linux 单机部署

#### 3.2.1 编译后端

```bash
# 交叉编译 Linux 二进制
$env:GOOS = "linux"
$env:GOARCH = "amd64"
go build -o bin/wxx-server ./server/cmd/server
```

#### 3.2.2 上传到服务器

```bash
# 上传二进制和配置
scp bin/wxx-server user@server:/opt/wxx/bin/
scp .env user@server:/opt/wxx/
scp -r server/migrations user@server:/opt/wxx/
```

#### 3.2.3 创建 systemd 服务

```bash
sudo cat > /etc/systemd/system/wxx.service << 'EOF'
[Unit]
Description=蔚小芯学工智能体后端
After=network.target

[Service]
Type=simple
User=wxx
Group=wxx
WorkingDirectory=/opt/wxx
ExecStart=/opt/wxx/bin/wxx-server
EnvironmentFile=/opt/wxx/.env
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable wxx
sudo systemctl start wxx
```

#### 3.2.4 配置 Nginx 反向代理（可选）

```nginx
server {
    listen 443 ssl;
    server_name api.pydaydayup.xyz;

    ssl_certificate /etc/letsencrypt/live/api.pydaydayup.xyz/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.pydaydayup.xyz/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. 环境变量配置

### 4.1 完整环境变量清单

| 变量名 | 必填 | 默认值 | 说明 |
|--------|------|--------|------|
| `DB_PATH` | 是 | `./data/wxx.db` | 数据库连接串。`libsql://` 开头为 Turso，否则为本地文件 |
| `APP_PORT` | 否 | `8080` | 服务端口（Vercel 部署时忽略） |
| `APP_MODE` | 否 | `debug` | 运行模式：`debug` / `release` / `test` |
| `LOG_LEVEL` | 否 | `info` | 日志级别：`debug` / `info` / `warn` / `error` |
| `JWT_SECRET` | 是 | - | JWT 签名密钥，至少 32 字符 |
| `JWT_EXPIRE_HOURS` | 否 | `2` | JWT 过期时间（小时） |
| `ZHIPU_API_KEY` | 是 | - | 智谱清言 API Key |
| `ZHIPU_BASE_URL` | 否 | - | 智谱 API 地址 |
| `ZHIPU_MODEL` | 否 | `glm-4` | 智谱模型名称 |
| `ZHIPU_4V_API_KEY` | 否 | - | 智谱 GLM-4V 多模态 API Key |
| `ZHIPU_4V_MODEL` | 否 | `glm-4v` | 智谱多模态模型名称 |
| `DEEPSEEK_API_KEY` | 否 | - | DeepSeek API Key |
| `DEEPSEEK_BASE_URL` | 否 | - | DeepSeek API 地址 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-v4-pro` | DeepSeek 模型名称 |
| `XFYUN_APP_ID` | 否 | - | 讯飞语音 APP ID |
| `XFYUN_API_KEY` | 否 | - | 讯飞语音 API Key |
| `XFYUN_API_SECRET` | 否 | - | 讯飞语音 API Secret |
| `XFYUN_SPEECH_URL` | 否 | - | 讯飞语音识别 API 地址 |
| `CORS_ALLOWED_ORIGINS` | 否 | `*` | 允许的前端域名（逗号分隔） |
| `XUEGONG_BASE_URL` | 否 | - | 学工系统对接地址 |
| `XUEGONG_TOKEN` | 否 | - | 学工系统对接 Token |
| `YBT_BASE_URL` | 否 | - | 一表通对接地址 |
| `YBT_TOKEN` | 否 | - | 一表通对接 Token |
| `SSO_BASE_URL` | 否 | - | SSO 认证地址 |
| `SSO_CALLBACK_URL` | 否 | - | SSO 回调地址 |

配置示例见 `server/.env.example`。

## 5. 一键部署脚本

### 5.1 脚本说明

项目提供一键部署脚本 `scripts/deploy-turso.ps1`，自动完成：

1. 检查 Vercel 登录状态
2. 收集 Turso 数据库信息
3. 执行数据库迁移（初始化 44 条种子数据）
4. 设置 Vercel 环境变量
5. 部署到 Vercel
6. 验证部署结果

### 5.2 使用方法

```powershell
# 1. 先登录 Vercel（首次需要）
vercel login

# 2. 运行部署脚本
pwsh scripts/deploy-turso.ps1

# 或带参数运行
pwsh scripts/deploy-turso.ps1 -TursoUrl "libsql://wxx-agent-xxx.turso.io" -TursoToken "eyJhbGci..."
```

### 5.3 前置条件

| 条件 | 说明 |
|------|------|
| Turso 数据库 | 已在 https://turso.tech 注册并创建数据库 |
| Vercel 账号 | 已注册 Vercel 账号 |
| Node.js | 已安装 v18+ |
| Go | 已安装 v1.21+ |
| 本地 .env | 已配置所有 API Key |

## 7. 常见问题

### 7.1 数据上传后刷新丢失（Vercel 部署）

**原因：** Vercel 无服务器函数使用临时文件系统，本地 SQLite 文件在冷启动后丢失。

**解决：** 必须使用 Turso 云数据库。设置 `DB_PATH=libsql://xxx.turso.io?authToken=xxx`。

### 7.2 数据库迁移失败

**原因：** Turso 不支持部分 SQLite PRAGMA 语句。

**解决：** 迁移工具已自动跳过 PRAGMA 语句（`server/cmd/migrate/main.go`）。如仍失败，检查 Turso 数据库 URL 和 Token 是否正确。

### 7.3 Vercel 部署超时

**原因：** Go 编译时间较长或依赖下载慢。

**解决：** 确保 `go.mod` 和 `go.sum` 已提交。Vercel 会缓存 Go 模块。

### 7.4 CORS 跨域错误

**原因：** 前端域名未在 `CORS_ALLOWED_ORIGINS` 中配置。

**解决：** 在 Vercel 环境变量中设置 `CORS_ALLOWED_ORIGINS=https://wxx-agent.pages.dev`。

### 7.5 Cloudflare 代理配置

前端通过 Cloudflare Pages Functions 代理请求到后端。代理配置文件：

`frontend/functions/api/[[route]].js`

当前代理目标：

```javascript
const targetUrl = 'https://wxx-server.vercel.app' + backendPath + url.search;
```

如需修改后端地址，更新此文件中的 `targetUrl`。

### 7.6 数据库连接池配置

| 部署模式 | MaxOpenConns | MaxIdleConns | ConnMaxLifetime |
|----------|-------------|-------------|-----------------|
| Turso 云数据库 | 5 | 10 | 5 分钟 |
| 本地 SQLite | 1 | 2 | 无限 |

本地 SQLite 使用单连接避免 "database is locked" 错误。Turso 支持并发连接。
