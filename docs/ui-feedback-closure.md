# 任务方案 — 反馈修复闭环：可靠提交 + 结构化复制 + 一键解决

> 版本：v1.0 · 2026-08-12

## 背景与目标

反馈管理现状：提交即入库（截图内联佐证）、管理端有复制与在线修复、可标记已解决。
但存在缺口：**用户提交失败会丢输入**（无草稿/重试）、**用户端「我的反馈」无复制按钮**、
**管理端修复→验证→解决未闭环**。目标：让管理员在本机开发环境"边使用、边修复 Bug、边增强功能"，
全程**完整、可靠、不丢数据**。

## 范围

### 做

1. **提交可靠性（不丢数据）**
   - 反馈对话框：输入内容/分类/模块在页面关闭或提交失败时**自动存本地草稿**（Hive/SharedPreferences 均可，项目已用 Storage 工具），下次打开自动恢复。
   - 提交失败：保留输入并提示重试；网络/500 均不丢字。

2. **结构化报告复用（统一不丢字段）**
   - 新增纯函数 `buildFeedbackReport(FeedbackEntry fb, {...})`（放 `utils/` 或 `models.dart`），生成完整结构化文本（JSON 全字段 + Markdown 展示，两者都提供），字段含：ID/用户/时间/类型/模块/内容/截图URL/关联资源/状态/回复/处理记录。
   - 三处复用：管理端详情「复制完整反馈」、在线修复面板「复制完整报告」、用户端「我的反馈」复制。

3. **用户端复制（我的反馈）**
   - `my_feedbacks_page.dart` 卡片与详情加「复制反馈」按钮，用统一报告函数。

4. **管理端闭环（修复→验证→解决）**
   - 在线修复面板底部，把「复制完整报告」与「标记已解决」串起来：提示复制后提交 AI → 验证 → 一键「已解决并回复」（回填 reply）。
   - 详情页在修复建议下方增加提示性闭环引导。

5. **文档登记**（`docs/ui-feedback.md`、`docs/ui-feedback-copy.md`）

### 不做
- 不改后端接口（纯前端增量；后端 Submit 已可靠入库）。
- 不做自动执行修复的 CI 联调（仍为"复制→AI 修复→人验证"）。

## 技术要点

| 项 | 说明 |
|----|------|
| 草稿存储 | 复用 `utils/storage.dart`（项目已有 Storage 封装，见 login_page 使用） |
| 报告函数 | 新文件 `frontend/lib/utils/feedback_report.dart`，纯 Dart 无依赖，三处复用 |
| 复制 | 沿用 `Clipboard.setData` |
| 无新依赖 | 无 pub 新增 |

## 步骤拆分

1. 新建 `utils/feedback_report.dart`：`buildFeedbackReport`（结构化 JSON + Markdown 双格式）。
2. `feedback_dialog.dart`：草稿保存/恢复 + 失败重试保输入。
3. `my_feedbacks_page.dart`：卡片/详情加复制按钮（复用报告函数）。
4. `feedback_page.dart` 详情与 `feedback_repair.dart`：复用统一报告函数 + 闭环引导（验证→标记已解决）。
5. 验证：`flutter analyze` / `flutter test` / 构建。
6. 文档 + 提交。

## 验收标准

- 反馈提交失败时输入完整保留，可一键重试；关闭对话框再打开自动恢复草稿。
- 「我的反馈」、管理端详情、在线修复面板三处的复制内容由同一函数生成，字段完整（含 ID/内容/状态/截图/资源/记录）。
- 管理端修复面板可指引「复制→AI 修复→验证→标记已解决」完整闭环。
- `flutter analyze` 0 error / 0 warning；`flutter test` 通过；Web 构建成功。

## 回滚与检查点
- 纯前端增量，Git 单次提交可回滚；草稿存储为本地 Hive/SharedPreferences，无服务端影响。
