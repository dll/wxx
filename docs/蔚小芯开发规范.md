## 3. 项目硬性约束（摘要）

以下内容承接《蔚小芯智能体》开篇约束，实施阶段 **不得默认违背**；若变更须走书面评审。

- **业务**：全院师生服务；多智能体管理中心、策略与元数据 **自研**；编排运行时 **可自部署开源框架（Eino）+ 自研封装**；关键链路可选 **Temporal**。
- **知识增强**：**必选**。主链路为 **Context Engine**：结构化数据（SQLite）+ **全文检索（FTS/BM25）** + 上下文拼装；**向量检索与 Agentic RAG 为可插拔**，按意图与触发策略启用；长文档按需 **Long Context**。
- **模型与部署**：使用 **智谱清言 / DeepSeek / 讯飞星火语音** 等 API；**不**本地部署大模型；**不**依赖 Coze 等第三方智能体 SaaS。
- **基础设施**：**不**强制 Docker/容器/集群；轻量化单机与服务化部署为主。
- **可信输出**：政策/条件类回答必须具备 **`sources` 可追溯**；低置信与未命中走兜底话术，**禁止编造条款与关键数字**。
- **全项目中文化**：所有文档、代码注释、Git 提交信息、错误提示、日志输出均使用中文。变量名与函数名用英文，但行内注释和文档注释必须中文。生成的 SKILL.md、README.md 等文件全中文。

## 4. Harness：AI 协作与工程纪律

蔚小芯研发全程采用 **Harness Engineering** 心智：**提示词 ⊂ 上下文 ⊂ Harness**。最小落地要求：

### 4.1 上下文架构

- 仓库根或 `WXX/` 内维护 **`AGENTS.md`**：百行级 **摘要 + 索引**，细则拆到 `WXX/docs/` 按需加载。
- 与业务相关的权威条文仍以《蔚小芯智能体》及 `docs/context-engine.md`、`specs/` 为准，避免在单文件堆积数千行规则。

### 4.2 执行能力

- 开发期可为 AI 助手配置 **MCP / Skills**（如文档检索、浏览器验证），但生产运行时第三方依赖须符合学院网络与安全策略。
- 对外部 API（学工、一表通、模型）的调用须有 **超时、重试与熔断** 策略（与智能体文档 §4、§9 一致）。

### 4.3 任务编排

- **先方案后编码**：复杂需求使用 Plan，经负责人确认后再改代码。
- **增量交付**：每完成可演示增量，更新对应说明文档并 **Git 提交**（检查点）；长会话污染上下文时 **新会话 + 关联文档** 恢复记忆。

### 4.4 反馈机制

- 合并前：**Lint、单元测试、必要时的 E2E/Browser 自测**；失败必须修复或标注豁免原因。
- 关键路径变更鼓励 **代码评审 / 双视角检查**（视同多 Agent 互审的人力版）。

### 4.5 架构护栏

- 区分 **风格 Lint** 与 **架构规则**（分层依赖、禁止 UI 直连 DB 等）；配合 **Pre-commit** 与版本历史，防止技术债无序膨胀。

## 5. 知识工程：Context Engine 为主，Wiki/RAG 为辅

### 5.1 产品侧（对用户可见知识）

严格执行《蔚小芯智能体》**§3.3 Context Engine**：

- **结构化优先** → **FTS/BM25 主召回** → **上下文拼装** → 模型生成；向量与 Agentic **按需**；手册类可 **Long Context**。
- **触发策略、Top-K、缓存策略、引用与元数据、切分规则** 以智能体文档 §3.3.x、§6.8 为准，不在本规范重复罗列数值时可指向 `WXX/docs/context-engine.md` 摘录表。

### 5.2 研发侧内部知识（可选 LLM Wiki 范式）

对照《RAGvsLLMwiki》：对于 **项目组内部** 的非实时资料（会议纪要、调研笔记、截图），可采用 **`knowledge/raw/` + `knowledge/wiki/` + 编译刷新** 的极简 wiki，用于人类与 AI 共读；**不得替代** 上线所需的 Context Engine 治理与审核流程。

### 5.3 何时考虑加重向量 / Graph / 混合检索

当命中率、兜底率、长尾同义问指标持续不达标时，按《RAGvsLLMwiki》第七节与智能体文档分期规划，**增量**引入向量补召回、重排或 Agentic，而非推翻主链路。

## 6. 技术栈与分层（固定口径）

| 层级 | 选型 | 说明 |
|------|------|------|
| 客户端 | Flutter + Dio + Provider + Hive | 微信小程序等按文档 §6.5 单独轻量实现 |
| 网关与业务后端 | Go + Gin + JWT + RBAC | 六级角色 |
| 持久化 | SQLite（业务、审计、结构化知识、FTS5） | 内存缓存为内置轻量缓存 |
| 编排 | Eino（必选方向）+ 自研 Agent Hub | Temporal 可选 |
| 外部智能 | 智谱、DeepSeek、讯飞 API | HTTP/SSE |

## 7. 接口与数据契约

- **REST/SSE 契约**：以《蔚小芯智能体》**附录 A/B** 为工作草稿；变更记录在 `WXX/specs/` 或变更日志模板中留痕。
- **知识导出 / 与「蔚园智答」同步**：遵循 **§6.8** `manifest.json` + `resources.ndjson` + 增量 cursor；签名与鉴权见 §6.8.9。

## 8. 统一回答与多端呈现

- 后端统一 **`AnswerCard`** 结构（结论、步骤清单、`sources`、风险提示、追问建议、可执行动作），详见智能体 **§3.5**。

## 9. 安全、隐私与 RBAC

- **检索前过滤**：`ownerScope`、`roleScope`、`status=published`。
- **敏感信息**：学号、手机、身份证等 **不得** 作为可检索正文入库；展示按角色脱敏。
- **RBAC**：六级角色能力与菜单矩阵以智能体 **§6.6** 及 `specs/rbac-matrix.md` 模板维护。
