# 蔚小芯 移动应用签名与发布（iOS + HarmonyOS）— v1 操作手册

> 状态：待凭据后执行 | 版本：v1 | 日期：2026-08-14
> 关联：`docs/移动应用构建与发布.md`（构建与未签名制品）、`.github/workflows/build-mobile.yml`
> 前提：已能产出**未签名** iOS `.app.zip` 与鸿蒙 `unsigned.hap`（详见上文档，含实测记录）。

## 〇、签名总览

| 项 | iOS | HarmonyOS |
|----|-----|-----------|
| 账号 | Apple Developer Program（个人/公司） | 华为开发者联盟 + AppGallery Connect（AGC） |
| 必要文件 | 分发证书 `.p12`、描述文件 `.mobileprovision` | 证书 `.cer`、证书库 `.p12`、Profile `.p7b` |
| 产物 | 签名 `.ipa` → TestFlight | 签名 `.hap` → AGC 上架 |
| CI Job | `build-ios`（macos-15） | `build-harmonyos`（ubuntu） |
| 触发输入 | `ios_target: signed` / `testflight` | `harmonyos_target: signed` |

> ⚠️ 所有签名文件与口令 **只存 GitHub Secrets**，禁止进仓库。CI 内用 `python3` 动态注入 `ExportOptions.plist` / `pbxproj` / `build-profile.json5`，仓库文件保持占位符。

## 一、iOS 签名（Apple Developer）

### 1.1 前置条件

- Apple Developer Program 账号（https://developer.apple.com）。
- 确定 Bundle ID：`com.wxx.wxxApp`（工程已固定，见 `frontend/ios/Runner.xcodeproj/project.pbxproj`）。

### 1.2 在 Apple Developer 后台操作

1. **注册 App ID**：Certificates, Identifiers & Profiles → Identifiers → 新建 → 类型 App → Bundle ID 填 `com.wxx.wxxApp`，勾选能力（无需推送则保持默认）。
2. **创建分发证书**（.p12）：
   - 本机（Mac）打开「钥匙串访问」→ 证书助理 → 从证书颁发机构请求证书，生成 `CertificateSigningRequest`（.certSigningRequest）。
   - 后台 Certificates → 新建 → **Apple Distribution** → 上传 CSR → 下载 `.cer`。
   - 双击导入钥匙串，右键导出为 `.p12`，**设置导出口令**（记下，作 `APPLE_CERT_PASSWORD`）。
3. **创建描述文件**（Provisioning Profile）：
   - Profiles → 新建 → **Distribution → App Store**（上架 TestFlight/App Store 用）。
   - 选择 App ID `com.wxx.wxxApp` + 刚才的分发证书 → 命名如 `wxxApp-Store` → 下载 `.mobileprovision`。
4. **App Store Connect API Key**（供 CI 上传 TestFlight）：
   - https://appstoreconnect.apple.com → 用户与访问 → 密钥（Keys）→ 新建，下载 `.p8`，记下 **Key ID** 与 **Issuer ID**。

### 1.3 配置 GitHub Secrets

| Secret | 内容 | 来源 |
|--------|------|------|
| `APPLE_TEAM_ID` | 10 位 Team ID（后台右上角 / 账号页面） | 后台 |
| `APPLE_CERT_BASE64` | `.p12` 文件的 base64 | 本机导出 |
| `APPLE_CERT_PASSWORD` | `.p12` 导出口令 | 本机导出 |
| `APPLE_PROFILE_BASE64` | `.mobileprovision` 的 base64 | 后台下载 |
| `APPLE_ASC_KEY_ID` | App Store Connect API Key ID | ASC 后台 |
| `APPLE_ASC_ISSUER_ID` | API Key 的 Issuer ID | ASC 后台 |
| `APPLE_ASC_PRIVATE_KEY` | `.p8` 私钥内容（原样，非 base64） | ASC 后台 |

生成 base64（本机命令）：
```bash
base64 -i dist_cert.p12          # → APPLE_CERT_BASE64
base64 -i wxxApp-Store.mobileprovision  # → APPLE_PROFILE_BASE64
```

### 1.4 CI 签名流程（workflow 已实现）

`signed` / `testflight` 时自动执行：
1. 解码 `.p12` / `.mobileprovision`，导入 CI 钥匙串（`security import`）。
2. 提取描述文件 UUID，安装到 `~/Library/MobileDevice/Provisioning Profiles/`。
3. 读取钥匙串中 `Apple Distribution` 证书名，注入 `frontend/ios/ExportOptions.plist` 的 `teamID` / `signingCertificate` / `provisioningProfiles`。
4. `python3` 将 `pbxproj` 的 `CODE_SIGN_STYLE` 改为 `Manual`、注入 `DEVELOPMENT_TEAM`、`CODE_SIGN_IDENTITY` 改为 `iPhone Distribution`。
5. `flutter build ipa --release --export-options-plist=ios/ExportOptions.plist`。
6. `testflight` 时用 `app-store-connect` CLI 或 `xcrun altool` 上传 `.ipa`。

### 1.5 触发

```bash
gh workflow run "Build Mobile Apps" -R dll/wxx --ref main \
  -f ios_target=signed -f harmonyos_target=unsigned
# 或 ios_target=testflight 上传 TestFlight
```

### 1.6 验证与发布

- 产物：`dist/weixiaoxin-ios-v<版本>.ipa`。
- `codesign -dv <Runner.app>` 可验签；或 `security find-identity -v -p codesigning` 看证书。
- TestFlight 上传后：TestFlight → 外部测试（需添加测试员）或内部测试组。
- 正式上架：App Store Connect → App → 新增版本 → 选择该构建 → 填写审核信息 → 提交审核。

## 二、HarmonyOS 签名（华为 AGC）

### 2.1 前置条件

- 华为开发者账号（https://developer.huawei.com/consumer/cn/ ）。
- 确定 Bundle Name：`com.wxx.weixiaoxin`（工程已固定，见 `frontend/harmonyos/AppScope/app.json5`）。
- **AGC App ID：`6917613658371109180`**（2026-08-14 AGC 后台创建「蔚小芯」应用后分配，用于生成签名 Profile 时绑定）。
- 本机已装 **DevEco Studio**（`D:\Program Files\Huawei\DevEco Studio`，hvigor 6.23.6）。

### 2.2 在 AGC 后台操作

1. **创建应用**：AGC 控制台 → 我的项目 → 新建项目 → 添加应用 → 平台 **HarmonyOS** → 应用名称「蔚小芯」→ 包名 `com.wxx.weixiaoxin`。
2. **生成签名证书三件套**（.cer / .p12 / .p7b）——推荐用 DevEco Studio 自动签名：
   - 打开工程 `frontend/harmonyos` → **File → Project Structure → Signing Configs**。
   - 勾选「Automatically generate signature」（需登录华为账号）→ 填写并确认。
   - 生成后文件位于：`frontend/harmonyos/build-profile.json5` 的 `material` 指向的路径（默认 `~/...` 或项目内），得到：
     - `xxx.cer`（发布证书）
     - `xxx.p12`（证书库，含 keyAlias / storePassword / keyPassword）
     - `xxx.p7b`（Profile）
   - 记下 `material` 中全部字段：`storePassword`、`keyAlias`、`keyPassword`。
3. **手动方式（备选）**：
   - AGC → 开发 → 证书管理 → 新建发布证书 → 上传 CSR（keytool 生成）→ 下载 `.cer`。
   - AGC → 开发 → 证书、APP ID 和 Profile → 新建 Profile → 绑定证书 → 下载 `.p7b`。
   - 本机 `keytool` 生成 `.p12`：`keytool -genkeypair -alias <alias> -keyalg EC -groupname secp256r1 -sigalg SHA256withECDSA -dname "C=CN,O=...,CN=<alias>" -keystore signing.p12 -storetype pkcs12 -storepass <pass> -keypass <pass>`。

### 2.3 配置 GitHub Secrets

| Secret | 内容 | 来源 |
|--------|------|------|
| `HUAWEI_SIGNING_CERT` | `.cer` 的 base64 | AGC / DevEco |
| `HUAWEI_SIGNING_P12` | `.p12` 的 base64 | AGC / DevEco |
| `HUAWEI_SIGNING_PROFILE` | `.p7b` 的 base64 | AGC / DevEco |
| `HUAWEI_SIGNING_STORE_PASSWORD` | `.p12` 存储口令 | DevEco material |
| `HUAWEI_SIGNING_KEY_ALIAS` | keyAlias（如 `debug` / `wxx`） | DevEco material |
| `HUAWEI_SIGNING_KEY_PASSWORD` | keyPassword（若与 storePassword 相同可省略，CI 会回退） | DevEco material |

### 2.4 CI 签名流程（workflow 已实现）

`harmonyos_target: signed` 时自动执行：
1. 解码 `.cer` / `.p12` / `.p7b` 到 `frontend/harmonyos/signing.*`。
2. `python3` 注入 `build-profile.json5` 的 `signingConfigs`（name=default，material 指向 signing 文件 + Secrets 口令）。
3. `hvigorw assembleHap --mode module -p product=default -p buildMode=release --no-daemon`（release 模式按 signingConfigs 签名）。
4. 产出 `entry-default-signed.hap`。

> ⚠️ CI 注入会**临时改写** `frontend/harmonyos/build-profile.json5`，仅存在于 runner，不影响仓库；仓库该文件保持 `signingConfigs: []`。

### 2.5 触发

```bash
gh workflow run "Build Mobile Apps" -R dll/wxx --ref main \
  -f ios_target=unsigned -f harmonyos_target=signed
```

### 2.6 验证与发布

- 产物：`dist/entry-default-signed.hap`。
- 本地验证：DevEco Studio → 打开 `frontend/harmonyos` → Run 到 HarmonyOS NEXT 真机（需打开开发者模式）。
- 上架 AGC：AGC 控制台 → 应用 → 应用信息 → **发布** → 新建版本 → 上传 `.hap`（AppGallery 需要审核）。
- 若需先内测：AGC → 分发 → 测试 → 创建测试用户/测试包分发。

## 三、发布到 GitHub Release（可选，与 APK 对齐）

签名产物构建成功后，可上传到同名 Release：

```bash
# 先 gh run download 获取制品，或在工作流内 softprops/action-gh-release
gh release upload v0.0.27 -R dll/wxx \
  dist/weixiaoxin-ios-v0.0.27.ipa \
  dist/entry-default-signed.hap --clobber
```

> 若需固定名下载入口（如 `weixiaoxin.ipa` / `weixiaoxin.hap` 指向 `releases/latest/download/`），可在 workflow 中上传固定名副本（与 APK 的 `weixiaoxin.apk` 策略一致）。

## 五、回滚与安全

- 凭据泄漏：立即在 GitHub 删除对应 Secret，重新生成签名证书/Profile 作废旧的。
- 签名失败排查：先看 workflow 日志中 `security import` / `PlistBuddy` / `python3` 注入是否成功，再查 `flutter build ipa` / `hvigorw` 的 codesign 报错（`xx.app: errSecInternalComponent` 多为钥匙串权限问题）。
- CI 注入只改 runner 内文件，回滚 = 重新 checkout。
