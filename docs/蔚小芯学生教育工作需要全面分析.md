# 蔚小芯学生教育工作需要全面分析报告

> **版本**: v1.0 | **日期**: 2026-08-03
> **方法**: 对 main 分支代码全量核查（Flutter 前端 + Go 后端 48 个迁移 + 本地部署库 `server/data/wxx.db` 实查）+ 前后端契约逐接口比对 + 关键铁证抽读复核
> **对照基线**: 《蔚小芯角色功能.md》v5.3（宣称 113 项全部 ✅ 已完成）、`docs/wxx-audit-report/` 审核报告
> **结论一句话**: **系统架构真实可运行、核心闭环（认证/问答/知识库/审计）确实可用，但"113 项全部完成"指"代码存在"而非"功能落地"；按"能否交付给学生教育工作实际使用"标准衡量，整体落地度约 40–50%。**

## 一、总体结论

### 1.1 两个层面分开看

| 层面 | 判断 | 依据 |
|------|------|------|
| **系统架构** | ✅ 真实可运行 | 104 项 capability + 8 角色继承（`auth/capabilities.go`）、真实 FTS5/BM25 检索、真实 LLM 调用（DeepSeek/智谱/讯飞）、异步审计日志（部署库 342 条）、Excel 导入、文档上传精修链路全部真实接线 |
| **功能落地** | ⚠️ 约 40–50% | 大量功能是「写死的演示数据」或「前后端契约错位导致界面空白」，数据底座（成绩/课表/行为）无导入通道 |

### 1.2 为什么文档宣称"全部完成"却未落地

"✅ 已完成"的判定标准是**路由存在 + service 有函数 + 页面存在**，但漏掉了三层硬指标：

1. **前后端契约对齐**：后端真做了事，前端读错字段 → 用户看到的仍是空白/兜底数据（约 15 处）。
2. **数据是否为演示**：`data_source: reference/fallback` 标记的写死数据是否被当作真实数据展示（教师/教辅/学生会大面积存在）。
3. **数据是否有真实写入通道**：成绩表 0 行、积分/问答/谈心表**根本不存在**。

### 1.3 关键量化

- 部署库 `kb_resources` **50 条**（含 2 条测试残留+乱码），距材料文档"≥50 条基础可用、200–500 优秀"的目标仅踩线。
- `student_grades` **0 行**、`exam_schedules` 0 行、`feedback` 0 行、`token_usage` 0 行；课表仅 `user_id=1` 的 10 条示例。
- 3 类核心业务表**未建**：`points`（积分成就）、`qa_posts`（问答广场/私聊）、`talk_records`（谈心记录）。
- 11 个学生 AI 页面只注册了 GoRoute、菜单无入口（**死路由**）。
- 学生会活动策划/海报生成前后端 **POST vs GET 方法不匹配**，请求 100% 失败。

## 二、六大链路逐环核查

### 2.1 材料 → 知识库 【真实可用，但规模与治理不足】

- 上传→解析→LLM 精修→质量门槛→入库→FTS 触发器同步全链路真实接线：
  `upload_handler.go:28` → `document_service.go:97`（txt/md/pdf/docx/xlsx 解析 + 乱码检测 + `RefineMetadata` LLM 精修）→ `kb_service.Create`。
- 知识治理状态机（draft/pending/published/retired）、审核流、批量操作真实存在（`kb_service.go:224/317/344/371/552`）。
- **问题**：
  - 部署库 50 条中 2 条是测试残留（`ndjson-001`、`test-import-001`，含乱码标题），说明上线前未做数据清理。
  - `knowledge/wiki/` 仅 2 个条目，尚未成为检索来源；知识治理的"运营循环"（每月补 FAQ、去重更新）无任何实际运转证据。
  - `server/data/seed/resources.ndjson` 的 50 条演示资源 source_link 全是 `example.edu.cn`，且代码无引用——不会被自动加载，但容易误导"已有种子库"。

### 2.2 知识库 → 问答 【真实可用，但存在双实现与宣传不符】

- 真实链路（`chat_service.go:105` `Ask`）：结构化优先检索（`SearchStructured`，命中≥3 跳过 FTS）→ FTS5/BM25 三阶段（短语/NEAR/宽松 OR，`kb_repo.go:43-96`）→ 相关性预检 `filterLowRelevanceResults` → 上下文拼装 `buildMessages` → 真实 LLM 调用 → `buildAnswerCard` 附加 `sources[]`，低置信清空 sources。
- **问题**：
  - **SSE 流式未实现**：`chat_handler.go:101` 一次 `c.JSON` 全量返回。文档宣称"SSE 流式"是虚假宣传；前端"打字机"体验是假流式。
  - **Context Engine 是孤儿包**：`server/internal/context_engine/` 有完整实现（意图分类/结构化优先/FTS/加权/片段提取）但生产装配（`app.go`）未接线，实际链路用 `chat_service.go` 内联副本。文档宣称的架构与实现脱节，双实现并存增加维护成本。
  - 意图分类实际由 `agent/router.go` 另一套关键词表承担，与 `context_engine/intent.go` 重复。
  - **Eino 未集成**：`go.mod` 无 eino 依赖，`agent/doc.go` 宣称"基于 Eino"实际是自研关键词路由 + goroutine 并行。文档与实际不符。
  - 知识规模 50 条 + 无运营循环 → 真实校园问题兜底率会偏高（无评测数据支撑）。

### 2.3 问答 → 学习 【半落地：学情看板无数据、学习日记 LLM 白调】

- **AI 学习日记（坏功能）**：`student_service.go:286-352` `generateDiaryWithLLM` 真实调 LLM，但 `parseDiaryJSON` 把解析出的 `text` **原样丢弃**，返回硬编码壳（只有一道写死的"二叉树前序遍历"自测题）。任何情况下用户都看不到 LLM 生成的学习日记，`data_source` 却标为 `"ai"`。
- **课程学情看板/课程地图**：
  - 后端真实成绩路径 `twin_repo.go:257 ListCourseGrades` 查 `student_grades`，但该表**全库无 INSERT 写入路径** → 恒空 → 必然回落 mock。
  - 即便有数据，后端返回单对象（嵌套 `courses`），前端 provider 期望 **List**（`student_feature_provider.dart:161`）→ 真实数据下页面反而"暂无数据"。
  - 课程地图 `GenerateKnowledgeGraph` 恒返回对象，前端恒解析失败 → 打开必空的死页面。
- **学习周报**：核心指标（时长/排名变化/改进建议）全部为写死模板，仅"近 7 天提问活跃度"是真实数据。

### 2.4 学习 → 画像 【半落地：数字孪生后端真、前端错位】

- **个人数字孪生**：后端是真实数据底座（`twin_repo.go:65` `AggregateRawMetrics` 聚合 8 张表 → 五维打分 → LLM 解读 → 落快照），本项目少数货真价实的部分。
- **但前后端字段完全错位**：后端返回 `interpretation / gap_analysis / stage_advice`，前端模型只解析 `ideal_dimensions / ai_summary / suggestions`（`models.dart:1354`）→ 生产环境"AI 分析"卡片与"成长建议"为空，只有雷达图 5 维分数可见。
- **学业维度恒为 0**：成绩/课表/行为无导入通道，五维中"学业/能力"只能靠用户自填的少量数据。
- **性格洞察（真实可用）**：`personality_service.go:66` 真实行为聚合 + LLM 推断 + 7 天缓存落库，字段对齐，是少数真功能。

### 2.5 画像 → 成长 【半落地：真实快照前端读不到 + 大量死路由】

- **成长路径规划**：后端 `GenerateGrowthPath`（`student_service.go:1682`）真实孪生快照 + 里程碑 + LLM，但返回结构无 `response/content` 字段，前端 `askAI` 只能读这两个字段 → **有孪生数据的学生打开反而"暂无内容"**。
- **新生大学规划/思政学习/思想成长档案**：全部是 `GenericAI` 纯文本页，**且是死路由（菜单无入口）**，正常学生点不到。
- **入党入团/心理模块**：存在真实 DB 模块（`party_education_page.dart`、`mental/` 子目录），但与死路由页重复，用户易混淆。

### 2.6 成长 → 育人闭环（辅导员侧）【半落地】

- **AI 今日关注（真实可用）**：`counselor_service.go` 真实 `emotion_logs` + LLM 叙事。
- **预测性预警**：基于真实告警的规则推导概率（非 ML），前端读 `reason/level` 后端无 → 副标题空、风险恒显示绿色。
- **AI 干预方案生成（占位）**：前端传 `student_id`，后端读 `student_name` → LLM 分支永不触发，永远返回模板方案。
- **谈心谈话记录（不落库）**：POST 有 LLM 结构化摘要但**无 `talk_records` 表**，GET 返回写死的假记录，保存后刷新即消失；**无语音转写**（只有文本输入）。
- **话术推荐（占位）**：前端传 `scene/type`，后端读 `profile` → 固定 5 条话术。
- **班级学情日报/思想档案/性格画像**：核心数据写死（`0.87/0.92/0.93`、`计科2301班`、"参与率95%"），仅告警数真实；班级性格画像字段错位恒"暂无画像数据"。
- **社区管理/热点感知（假）**：前端调 askAI 但忽略返回值，渲染写死 demo（"转专业经验分享/张三/今日发帖23"），审核按钮 `onPressed: () {}` 空操作。

## 四、问题清单（分级）

### P0 — 阻断性（不修则"功能存在但用户永远看不到/拿到假数据"）

1. **教师 AI 出题/批改/课堂互动 LLM 输出被丢弃**：`teacher_service.go:159-184`（`generateExamWithLLM` 等三处调用 LLM 后直接 `return s.fallbackExam(...)`）。
2. **AI 学习日记 LLM 输出被丢弃**：`student_service.go:329-352` `parseDiaryJSON` 抽出 `text` 后未使用，返回硬编码壳。
3. **学生会活动策划/海报生成前后端方法不匹配**：前端 `POST`（`event_plan_page.dart:29`、`poster_gen_page.dart:31`）vs 后端 `GET`（`app.go:1075-1076`）→ 100% 失败。
4. **数字孪生/成长路径前后端字段错位**：后端 `interpretation/stage_advice` 等，前端读 `ai_summary/suggestions`（`models.dart:1354`）→ 数据越真界面越空。
5. **课程学情/地图数据链断裂**：`student_grades` 无写入通道 + List/对象错位 + 前端解析恒失败。
6. **问答广场/热点/排行榜前端丢弃后端结构化数据** → 恒显硬编码 demo，社区从未真正存在。

### P1 — 重要（数据底座/死路由/假数据，直接影响"能否用起来"）

7. **成绩/课表/行为无导入通道**：`student_grades` 0 行，数字孪生学业维度恒 0；教务数据（排课/毕业/考试）无法进入系统。

## 七、回答四个核心问题

1. **蔚小芯智能体能满足学生教育工作的需要吗？**
   **目前不能，但架构已具备条件。** 核心问答/知识库/认证/审计真实可用；但按"落地功能"标准，学生约 50%、辅导员约 40%、学校/系统管理员约 80%、教师约 20%、教辅约 15%、学生会约 10%。"能支撑一场演示/验收"≠"能支撑真实日常工作"。

2. **从材料到知识库、问答到成长、学习到画像的链路通了吗？**
   材料→知识库→问答 ✅ 真实打通（规模与治理待加强）；问答→学习/画像 → ⚠️ 半通（后端真实、前端错位、成绩无数据）；画像→成长 → ⚠️ 半通（真实快照读不到）；成长→育人闭环 → ❌ 弱（谈心不落库、干预不触发）。

3. **现在的问题有哪些？**
   见[第四章问题清单](#四问题清单分级)：核心是 **P0 断链**（约 15 处前后端错位 + 4 处 LLM 白调 + 1 处方法不匹配）+ **P1 数据底座缺失**（成绩/积分/问答/谈心无表无通道）。

4. **建议下一步？**
   按第六章节分期执行，先修阶段一（契约对齐 + 方法修复 + 开死路由），再修阶段二（去演示化），让"已宣称完成"的功能真正可见、可用、可交付。
