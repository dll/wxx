# 办事流程管理

## 现状与入口

- 办事页不再是硬编码的 5/6 个流程，而是从知识库 `Process` 资源动态读取已发布流程。
- 默认只展开「新生相关」，其他流程折叠；学生仍可在「只看新生相关」关闭后查看全部。
- 学校管理员、学院管理员、辅导员（`counselor.kb.write` / `counselor.kb.review`）在办事页右上角可进入「办事管理」「办事审核」。

## 数据模型

流程定义继续复用 `kb_resources`（`resource_type='Process'`），步骤使用 `process_steps`，提醒使用 `process_reminders`：

| 表 | 作用 |
|----|------|
| `kb_resources` | 流程标题、摘要、正文、归属、角色范围、发布状态 |
| `process_steps` | 步骤、材料、截止时间、地点、联系人、FAQ 等 |
| `process_reminders` | 时间节点、提醒标题、提醒内容、关联步骤、启停状态 |

## 管理流程

1. 办事页右上角「流程管理」→ 新建流程。
2. 填写基础信息、办理说明、步骤和提醒。
3. 保存后为草稿；点击「提交审核」进入待审核。
4. 「办事审核」页由学校/学院管理员（及辅导员）通过或驳回。
5. 已发布流程可下架；支持预览、打印、导出 PDF/PNG/Markdown、编辑、删除。

## 接口

- `GET /api/v1/process/definitions`：学生可见流程列表（含步骤与提醒）。
- `GET /api/v1/process/definitions/:id`：流程详情。
- `GET /api/v1/process/admin`、`POST/PUT/DELETE /api/v1/process/admin`：管理端 CRUD。
- `GET /api/v1/process/admin/pending`：待审核流程。
- `POST /api/v1/process/admin/:id/submit|approve|reject|retire`：审核与状态流转。

## 提醒

学生端按流程展示提醒节点，并根据日期和办理进度显示「待办 / 已到期 / 已完成」。管理员可在流程编辑页维护时间节点、内容、关联步骤和启停状态。
