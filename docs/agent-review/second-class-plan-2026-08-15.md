# 第二课堂功能补充方案（辅导员侧 · 2026-08-15）

> 用户要求：「第二课堂不能没有，所有缺少都要补充」
> 原则：**Plan → 人审 → 编码**；不造假；绩效/学分只来自真实记录。

## 一、现状核实（已实证 · 本地 server/data/wxx.db）

### 1. 知识库
- `kb_resources` 152 条（全部 published），含"第二课堂"字样的仅 4 条，**全是学风建设新闻**（顺带提到「第二课堂达标率」），**不是**《滁州学院本科生"第二课堂成绩单"制度实施办法》原文。
- 源文档 `data/滁州学院本科生"第二课堂成绩单"制度实施办法.md` 存在但**未入库** → 知识库答不出制度细节（学分要求/认定流程/学时等级）。

### 2. 活动体系（第二课堂的落地载体）—— 功能链路真实可用
- 表：`health_activities`（活动）、`health_activity_signups`（报名/签到/到场）、`student_points`（积分）、`clubs`/`club_activities` 等。
- **后端+前端已联通**：学生会 `activity_manage_page` 已能 创建活动/报名/签到/到场 全流程（HealthProvider → /health/activities API）。
- **但表内 0 真实数据**（health_activities 0 行、signups 0 行、student_points 0 行、club_activities 0 行）—— 只有壳，没有真实使用记录。

### 3. 辅导员侧
- **无**任何「第二课堂」专属入口/看板（辅导员工作台只有预警/谈心/学情/名单/孪生，见上轮）。

## 二、方案：三块，全部真实不造假

### A. 制度文档入库（补知识库空缺）✅ 最低成本、即可交付
把 `data/滁州学院本科生"第二课堂成绩单"制度实施办法.md` 正式导入 `kb_resources`：
- 一条迁移 SQL（或导入脚本），字段：`resource_type='official_doc'`（或 'Policy'）、`role_scope=['student','counselor','assistant','college_admin']`、status='published'、标题/正文/来源完整。
- 产物：知识库/问答能准确回答第二课堂制度内容。

### B. 辅导员「第二课堂」工作台入口 + 看板（接真实活动链路）
- 辅导员工作台新增「第二课堂」卡片区，含两个真实入口：
  1. **班级第二课堂看板**（新页面）：查本班学生第二课堂参与/积分，数据源 = activity 报名/签到记录 + student_points（真实，0 数据则诚实显示"暂无记录"）。
  2. **发起第二课堂活动**（复用学生会活动发起能力，新建辅导员发起入口）→ 写入 health_activities（与学生会活动同库，共用报名/签到链路）。
- 不挖空壳：卡片/看板全部接真实 API，无数据时页面明确"暂无记录"提示，不做假数字。

### C. 诚实边界（明确不做/标注）
- **不伪造积分/学分**：student_points 空即空，看板显示 0 或"暂无"，等真实活动产生记录。
- **学分换算规则**：若制度文档定义了学时→学分，先入库；积分换算只做「展示规则」，不自动造历史分。
- 不做超出范围的（审核 P1 社团体系合并），除非用户追加。
