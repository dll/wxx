# 蔚小芯 全角色 × 四维 系统性审核（2026-08-15）

> 审核对象：从**学生 → 教辅(辅导员/教师/教学助理) → 学院书记 → 学校书记** 的完整角色链。
> 审核四维：**① 需求契合度（是否满足该角色诉求）② 粘性（是否愿意回访）③ 数据贯通（上下级数据是否一条链）④ 流程通畅（提交→办理→审核→反馈是否闭环）**。
> 审核基线：真实数据可追溯、不瞎编；角色/能力见 `capabilities.go`，数据底座见各迁移文件。

## 一、逐角色审核

### 1. 学生（大一新生视角，全人教育主角）
- **需求契合 ★★★★**：从报到/入学指南、办事流程、学业/成绩、心理/健康、竞赛、入党、社团到就业、毕设全覆盖；"一问就解决"的 AI 问答 + 办事 × 提醒是核心。新生指南/报到节点/新生日程已落地（见 `freshmen_guide/freshman_onboarding`）。
- **粘性 ★★★★**：每日打卡、学习周报、AI 简讯、词元/成就激励；情绪日记/量表、数字孪生五维画像给自己"照镜子"。**弱点**：一旦办事一问就懂、打卡流于形式，缺乏"必须回来"的理由（无学分/无强制）。
- **数据贯通 ★★★★**：学生自身上行数据最全（成绩/竞赛/党建/心理/健康/活动/情绪都有真实表）；**下行（学生看自己）畅通**；上行（教辅/书记看学生）也已通。**缺口**：学生「自报数据（去向/打卡/情绪）」与「组织确认数据」混在同一视图，虽有 `data_source` 标注但学生自己未必感知差异。
- **流程通畅 ★★★★☆**：办事流程（预约/提醒）、毕设选题、竞赛报名、就医/心理预约、毕业去向自报→教辅审核，均提交→办理→反馈闭环。仅个别需线下（教务课表SSO）无法代查。

### 2. 辅导员（counselor）
- **需求契合 ★★★★**：今日关注、班级看板、**情感预警+干预**、谈心记录+话术、思想动态、班级画像、预测预警——精准对应辅导员三大职责（思想/心理/班级管理）。
- **粘性 ★★★★**：情感风险预警"主动找上门"（系统推高危学生）+ 谈心记录 → 干预 → 复查闭环，是强回访理由；数字孪生看板 + 班级学情日报提供"每日必看"。
- **数据贯通 ★★★★**：继承学生会→学生，能看到本班/本院学生五维、情绪、思想动态；谈心记录回流书记看板。**强项**：`counselor.twin.board` + `class.profile` 直接吃孪生快照。
- **流程通畅 ★★★★**：告警→处理→情感分析→干预方案→复查闭环完整；谈心记录带记录人真实可回溯。

### 3. 教师（teacher）
- **需求契合 ★★★☆**：备课、出题、课堂互动、作业批改、教学反思、班级热力图、学习风格。**弱点**：备课/批改等 AI 助手在"真实数据未配置时"降级为空壳（`teacher_service.go` TODO），一旦学生成绩/作业数据没进系统，价值打折。
- **粘性 ★★★**：**最弱一环**。缺乏高频刚需；热力图/风格分布依赖真实成绩数据，数据不满时"无东西可看"。**亮点**：竞赛指导教师榜（按 advisor_name 归集，呼应"教师必须带竞赛"）给教师额外的被认可激励。
- **数据贯通 ★★★**：与学生的链 = **课表(teacher)+竞赛指导教师(advisor_name)+成绩(教师录入)**，`triple-linkage` 已真（教师三方绑定真实化已落地）。**但**：学生课程学情(GPA)是学生侧 `self.course.analytics`，教师侧看的是班级聚合，两级口径需对齐。
- **流程通畅 ★★★☆**：排课/考试/毕业审核是教辅(assistant)职责，教师本人"办事"需求少；竞赛带指导教师已闭合。

### 4. 教辅 / 教学助理（assistant）⭐ 粘性高地
- **需求契合 ★★★★**：排课冲突检测、毕业审核、考试安排、教学日历、学生信息、通知，+ **后勤服务台**（实验/保洁/热水/查岗/环卫/借阅）+ **毕业去向登记审核**——全是教辅高频日常事务。
- **粘性 ★★★★**：**真实登记 → 统计看板 → 绩效画像** 是强回访理由（干了活有据可查、能进绩效）。后勤服务台并入教辅角色后，成为教辅的"工作台"。
- **数据贯通 ★★★★**：后勤记录、去向记录均带 `data_source='real'` + 操作人 + 审核流，与绩效画像（staff-performance-twin）链接，**唯一"登记→绩效"全闭环角色**。
- **流程通畅 ★★★★**：后勤登记、毕业去向「学生自报/教辅录入 → 教辅审核 → 书记看板计入」已闭环（迁移 086/087 + 路由 + 前端全齐）。

### 5. 学生会（student_union）
- **需求契合 ★★★☆**：活动策划、海报生成、知识库提交/反馈管理、活动签到（activity_attend）。但**活动体系(club_activities)未做完整合并**（P1-5 范围外），活动管理偏单点。
- **粘性 ★★★**：活动场景低频；海报/策划是创作型需求，新鲜感过了易弃。
- **数据贯通 ★★★☆**：活动签到 → 学生社交维度（五维 social）有联结；但学生会缺一张"本部门活动成效"看板。
- **流程通畅 ★★★☆**：活动报名→签到闭环有；但"活动发布→成果→纳入书记育人归因"未打通。

### 6. 学院书记（college_admin）
- **需求契合 ★★★★**：**同时继承辅导员+教师+教辅三线**（多父继承），加上本院用户/审计/指标/数字孪生大屏/数据分析/问题预案，再叠加**教育成果大屏**（竞赛/入党/学业/毕业去向）——学院书记的育人总览基本齐。
- **粘性 ★★★★**：数字孪生大屏 + 教育成果大屏是"向学院汇报"的刚需素材；跨学院对比提供管理决策视角。
- **数据贯通 ★★★★**：继承三线 → 本院学生全维度可见 + 教育成果聚合（college 参数按院过滤）。**薄弱**：五维孪生 **全校/全院聚合接口缺失**（full-education-closed-loop 缺口2），现只能看单学生或看板缓存。
- **流程通畅 ★★★★**：本院审计、指标、毕设管理、去向审核（继承教辅）均通。

### 7. 学校书记（school_admin）⭐ 最终买家
- **需求契合 ★★★★**：全校数字孪生全景、跨学院对比、学情总览、统计看板、教育成果大屏（全校），`role_perspective` 给管理者回答视角。**已有真实绩效报告**：全景/对比/学情/看板全 `DataSource=real`。
- **粘性 ★★★★**：**全校育人总览/跨学院排名** 是书记反复查看汇报的刚需。
- **数据贯通 ★★★★**：`user_id` 串全链路：入学(users 录取字段)→在校(五维/成绩/竞赛/党建/活动)→离校(process_records)→就业(**graduation_outcome 新表**)。**全生命周期唯一缺表已补**。
- **流程通畅 ★★★★**：一级看板数据全部真实聚合；党建漏斗/党课数据存在但书记侧接线待做（party-closed-loop 缺口）。

### 8. 系统管理员（sys_admin）
- **需求契合 ★★★★**：全局配置、审计日志（audit_logs 证据底座）、密码重置、AI 简讯管理、知识库同步导出。
- **粘性 ★★★**：运维低频，靠"全局审计/健康"被动值班。
- **贯通/流程 ★★★★**：全局审计可回溯所有人操作，是数据可信的兜底。

## 二、数据贯通：学生→书记 全链路核查

**结论：数据链路已通，但"聚合→归因"最后一级未闭环。**

```
学生(users 074 录取字段)              ✅ 入学
  ├─ 学业 academic  → student_grades/courses        ✅
  ├─ 能力 ability   → competitions(+advisor_name)   ✅ 教师"带竞赛"已真
  ├─ 思想 ideological → party_* 党建五阶段          ✅ 数据在，书记侧接线待做
  ├─ 情感 emotional → emotion_logs/psych 风险预警   ✅ 辅导员→全校风险聚合已有
  ├─ 社交 social    → clubs/activity_attend         ✅ 活动签到
  ├─ 身体 health_*  → 体测/日常/活动                ✅
  └─ 就业毕业 → graduation_progress/thesis + graduation_outcome(新) ✅ 去向唯一缺表已补
        │
        ▼
student_profile_snapshot(043) 五维快照              ✅ 学生/辅导员/学院大屏复用
        │
        ▼
辅导员看板(counselor.twin.board) / 学院大屏(college.twin.screen)  ✅
        │
        ▼
学院书记(HasCap counselor+teacher+assistant 多父)   ✅
        │
        ▼
学校书记: 全景/跨学院对比/学情/教育成果大屏(087)      ✅ 一级聚合真实
        │
        ▼
❌ 育人归因: 育人动作(谈心/后勤/活动) × 学生五维趋势  ⛔ 未挂钩（不瞎编红线内）
```

**贯通硬证据**：
- `student_profile_snapshot` 注释明示「供辅导员看板、学院大屏」，按 owner_scope/owner_id 聚合，口径统一。
- 迁移 087 `graduation_outcome` 补上全生命周期唯一缺表（就业/升学），`user_id` 串入学→离校→就业。
- `audit_logs` 全程记录操作，是"谁做了什么"的证据底座。

**三大未贯通点（诚实列出）**：
1. **育人归因 0%**：教师/教辅育人动作(谈心/后勤/活动)未与学生五维趋势挂钩，答不出"哪些育人努力带来学生变化"。这不是缺少点，是**归因方法论风险**（样本不足易过度归因），需按"只做趋势/相关性、不做因果"的诚实边界设计。
2. **学院书记缺"五维全校/全院聚合"**：现只能看单学生或看板缓存，无"一屏看全人教育"的学院聚合接口（full-education 缺口2）。
3. **党建子系统**：数据(五阶段/党课时长/介绍人)全在，但书记侧 `SelfParty` 自报读不到 → 党课漏斗看板待接线。

## 四、粘性深挖：谁"必须回来" vs 谁"会弃"

**强回访（每角色都有硬理由）**：
- 学生：办事 × 提醒、情绪日记/测评、学习周报、成就积分
- 辅导员：情感风险"主动推送"、谈心干预复查闭环
- 教辅：真实登记→绩效画像（干了活有绩效）
- 学院/学校书记：数字孪生+教育成果大屏（汇报刚需）

**脆弱点（新鲜感易散）**：
- 教师：无高频回访理由，AI 助手数据不满时是空壳
- 学生会：活动低频
- 学生：办事"一问就懂"后无"必须回来"的钩子（无学分/无强制）

**粘性提升杠杆（按优先级）**：
1. **教师端补数据**：成绩/作业真实入库 → 热力图/风格分布/批改才有价值（否则教师弃用）
2. **育人归因看板**：让教师/教辅看到"我的育人动作→学生变化"的正反馈（提升三端粘性）
3. **党建接线**：书记能看到党课漏斗 → 书记回访 + 反向推动党建活动登记
4. **打卡/自报挂钩**：学生自报(去向/情绪)与组织确认打通，给学生"被看见"的归属感
