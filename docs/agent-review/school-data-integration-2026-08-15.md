# 蔚小芯·学校系统课表数据接入方案（阶段设计）

- 日期：2026-08-15
- 目标：学生点击"个人中心 → 填教务/门户账号密码 → 蔚小芯代查课表 → 首页今日课表 + 学习计划 + 提醒"
- 原则：**准确性第一、合规优先、尊重学生授权边界、不绕过学校安全防护**

## 二、合规边界（必须遵守）

1. **个人授权代查**：仅允许学生**用自己的账号**查**自己**的课表；蔚小芯不缓存/不聚合他人课表数据。
2. **凭据安全**：绝不明文存密码；服务端用密钥加密；仅用于定时拉取本人课表；拿不到即报"暂无法获取"，不静默失败。
3. **不绕过验证码/风控**：教务设置了 `captcha` 即为防自动化保护，**不得用 OCR 自动破解验证码**规避机制（有合规与法规风险）。
4. **数据准确性**：展示注明"数据来自教务系统，仅供参考，以学校/教务系统为准"。
5. **不主动代理他人账号**：辅导员/班委"导入"仅限使用其**已授权**的导入通道（现有 `ImportSchedules`），不代爬学生个人账号。

---

## 三、数据来源三条路径（对应你的问题）

### 路径 A：官方/授权数据接口（阶段 2 · 最稳 · 推荐）
向学校申请开放统一身份认证/OAuth 或教务数据接口（今日校园、一表通常有）。学生授权 `蔚小芯`（OAuth 授权），蔚小芯通过接口拉取课表。
- 优点：合规、稳定、无验证码难题
- 缺点：需校方配合开放（当前**暂无 API**，列为待办）

### 路径 B：管理员/班委/辅导员导入（阶段 0.5 · 现有通道 · 立即可用）
现有 `ImportSchedules` + `course_schedules` 表 + 学生端首页今日课表/学习计划已通。
- **这是当下唯一合规、可立即跑通的数据路径**
- 由辅导员/教务员用**已授权渠道**（如教务导出课表文件）批量导入
- ✅ 已增强（commit 1e3231f）：数据导入页新增「课表字段说明」帮助面板（逐字段解释 + 节次时段对照），非技术人员也能填对 JSON，导入准确不踩坑
- ✅ 学生侧（阶段0，commit 87b1461）：首页今日课表「下一节课」状态徽章提醒

### 路径 C：学生个人授权代查（阶段 1 · 需校方确认 · 有验证码障碍）
学生填自己账号 → 蔚小芯登录其账号 → 查本人课表。
- **技术障碍**：CAS + 验证码，自动登录需过验证码；**在未获校方明确许可前，不进行自动登录采集**。
- 若校方认可"个人代查"且放开验证码风控，则可在"加密凭据 + 仅查本人 + 明确标注"前提下试点。
- **当前状态：架构已设计，未激活真实采集（等校方允许 + 门户/验证码可达）**

## 五、待确认决策点（给项目组/校方）
1. **是否可开启"个人授权代查"**：若学校愿意允许学生个人授予蔚小芯查本人课表，且教务验证码不拦自动化，则推进路径 C 试点；否则维持路径 B。
