# 书记视角 × 蔚小芯：育人绩效报告能力分析（2026-08-15）

> 背景：本项目源自书记构想。书记 = 学校/学院两级管理者。本文核实蔚小芯能否支撑「书记出色完成教育学生工作」，以及现有/应有绩效报告。

## 一、书记角色定位 = 系统已有两级管理员
- `school_admin`（学校书记）、`college_admin`（学院书记）均已存在；`sys_admin` 为系统管理员。
- `college_admin` **同时继承 counselor+teacher+assistant 三条业务线能力**（capabilities.go 多父继承），即学院书记可看教学/辅导/教辅三线数据。
- `role_perspective.go` 已为两级定义管理者回答视角（政策依据/统计口径/决策风险/跨学院对比）。

## 二、书记现在能看到的真实绩效报告（已有）
| 报告 | 路由 | 数据 | 是否真实 |
|---|---|---|---|
| 全校数字孪生全景 | school `/panorama` | 学生总数/学院数/风险学生/按学院明细 | ✅ `DataSource=real`（aggregateSchoolReal） |
| 跨学院对比 | school `/college-comparison` | 按指标排名 | ✅ real/fallback 诚实切换 |
| 校级学情总览 | school `/academic-overview` | 学院排名 | ✅ |
| 统计看板 | admin `/stats/dashboard` | 用户/知识库/对话/反馈四类 | ✅ 真实 SQL 聚合 |
| 系统健康/知识质量/用户行为 | sys `/system-health` 等 | 系统运营 | ✅ |

> 且 `GenerateSchoolPanorama` 的 LLM 解读明确提示「不得编造未提供的数字」，符合不瞎编。

## 三、书记真正缺的「育人绩效」——差距分析
现有报告偏两大块：**系统运营**（对话/反馈/知识库）与**学生风险/学情**（全景/对比）。
书记作为育人工作第一责任人，最关心的是**「谁在育人、育人成效、能否归因」**，这部分目前薄弱/缺失：

1. **育人工作负载**：教师/教辅实际做了多少育人动作（谈心/排课/评教/后勤/答疑）——目前只有个人绩效画像（GetStaffTwin），**缺全校/全院汇总**，书记看不到整体。
2. **育人效果归因**：学生成长（五维数字孪生快照 twin_snapshots）**未与具体教师/教辅的育人动作挂钩**，无法回答「哪位老师、哪类干预带来了学生改变」。
3. **闭环证据链**：从「书记决策部署 → 教辅教师执行 → 学生转变 → 绩效反馈」的完整链缺最后一环（育人效果如何回流到书记看板）。

## 四、蔚小芯如何「出色完成教育学生工作」（规划方向，未实施）
面向书记可新增 3 类绩效报告（均基于系统已有真实数据表，不引入虚构源）：
1. **育人工作总览（全校/学院）**：聚合各教辅/教师的 talk_records、facility_records、audit_logs（谈心数/后勤服务/工具调用），按学院下钻——回答「育人工作做了多少、谁在做」。
2. **学生成长成效看板（趋势+归因）**：用 twin_snapshots 五维快照算趋势，结合育人动作表做轻量归因——回答「学生往哪变、哪些干预有效」。
3. **决策支持（书记命令中心）**：在现有 cross-college 对比 + policy-simulation 之上，把育人绩效纳入对比维度。
 
> 注意：以上为**待实施方向**，需先确认数据口径（尤其归因需界定清楚、避免过度归因的"不瞎编"风险）。

## 五、诚实边界
- 全校全景/学情报告已真实；**育人绩效汇总与归因目前为 0，未上线任何编造数据**。
- 落地方案需守住：「育人负载」可按 audit/记录表如实聚合；「归因」若不满足统计显著性宁可只做"变化描述"不做"因果断言"。
