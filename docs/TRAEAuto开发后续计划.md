### 任务 2：站内通知系统

**数据库迁移（server/migrations/038_notifications.sql）**

```sql
CREATE TABLE IF NOT EXISTS notifications (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    content TEXT,
    type TEXT NOT NULL DEFAULT 'system', -- system/feedback/knowledge/activity
    related_id INTEGER,
    is_read INTEGER DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_notifications_user ON notifications(user_id);
```

**后端接口**
- GET `/api/v1/notifications` — 我的通知列表（分页）
- GET `/api/v1/notifications/unread-count` — 未读数量
- PUT `/api/v1/notifications/:id/read` — 标记已读
- PUT `/api/v1/notifications/read-all` — 全部已读
- POST `/api/v1/admin/notifications/send` — 管理员发送系统通知

**前端**
- 顶部导航栏通知铃铛图标（显示未读数）
- 通知中心抽屉/页面
- 通知列表（按类型图标区分）
- 点击通知跳转到对应页面

## 六、风险与注意事项

1. **数据库迁移**：新增表使用 `CREATE TABLE IF NOT EXISTS`，确保幂等
2. **向后兼容**：新增接口不影响现有接口，新增字段使用默认值
3. **性能考虑**：统计接口注意 SQL 查询效率，避免 N+1 查询
4. **安全防护**：新增接口遵循现有 RBAC 权限模型
5. **用户体验**：新增功能与现有 UI 风格保持一致
