## 2. 项目背景与建设目标

### 2.1 建设背景

现有油气业务数据通常分散在地质资料、钻井工程、生产日报、SCADA、物联网设备、图件、文档和外部集团系统中，存在数据来源多、口径不一、实时与历史数据分离、业务协同链条长、分析结果难以追溯等问题。

本项目拟建设统一的平台软件，将地质、工程、生产、实时监控、综合展示和公共数据治理能力纳入同一业务体系，形成“数据接入—标准化—业务应用—分析展示—质量治理—审计追溯”的闭环。

### 2.2 总体目标

1. 建设油气藏地质资料的统一管理和查询分析能力；
2. 建设覆盖钻井、固井、井控、钻井液、控压钻井、监督、压裂和试油等环节的工程管理能力；
3. 建设生产计划、调度、预警、曲线和报表能力；
4. 接入 SCADA 与物联网数据，提供点位管理、映射转换、质量码、存储和运行监控；
5. 建设首页综合驾驶舱和“一张图”，支持总览、专题分析和逐级下钻；
6. 建设数据标准、质量规则、文档管理、需求管理和流程中心；
7. 通过统一组织、权限、流程、消息、日志、审计和配置能力支撑各业务域安全运行；
8. 为集团平台、统一认证、资源智管平台和 AI 服务预留标准集成能力；
9. 通过分批上线、数据初始化和培训试运行，形成可持续运营的平台基础。

### 2.3 建设原则

- **统一标准：** 统一编码、字典、单位、坐标、时间、井号、设备和组织口径；
- **分域建设：** 业务域相对独立，公共底座统一复用；
- **实时与历史兼顾：** 实时数据用于监控和预警，历史数据用于查询、趋势和分析；
- **数据可追溯：** 重要数据、修改、审批、导入、接口和发布动作必须留痕；
- **权限最小化：** 按组织、角色、业务域、数据范围和操作权限控制访问；
- **先确认后开发：** 对需求、接口、数据、原型、口径和验收标准实行版本化确认；
- **边界清晰：** 现场设备、通信链路、商业组件、云资源和测评认证不默认包含在软件实施费中；
- **分批交付：** 先完成公共底座和核心数据模型，再按业务域逐批上线。

## 3. 项目范围与交付边界

### 3.1 本期软件实施范围

本期以 178 项功能点为范围基准，软件实施范围包括：

1. L01 地质管理；
2. L102 工程管理；
3. L03 生产管理；
4. L04 SCADA 与物联网监控平台接入侧能力；
5. L05 首页一张图与综合驾驶舱；
6. L06 数据及公共管理；
7. 组织、用户、角色、权限、流程、消息、字典、日志、审计、配置等公共底座；
8. 集团/供应商/SCADA 等接口的对接、数据映射、初始化和联调；
9. 项目管理、测试、部署、培训、试运行和验收支持。

### 3.2 原则上不包含的内容

以下内容不纳入软件实施报价，或需单独核价：

- 井场、站场的传感器、PLC、RTU、边缘网关及现场安装改造；
- 井场专线、VPN、4G/5G、视频链路及运营商服务；
- 云主机、关系型数据库、时序数据库、对象存储、分析型存储、备份资源；
- 防火墙、WAF、堡垒机、漏洞扫描、工控安全设备及安全测评费用；
- 等保、密评、信创适配认证及第三方测评费用；
- SEG-Y 专业解析/解释商业组件、GIS/三维引擎商业授权；
- Office/PDF/视频转码等商业授权；
- 集团资源智管、统一认证、AI 服务本身及对方系统改造费用；
- 短信、地图、视频、模型 API 等按量计费服务；
- 甲方未提供接口、数据或业务专家导致的额外数据治理和现场改造工作。

### 3.3 需求变更原则

下列情况应进入需求变更流程：

1. 新增业务域、功能点、角色或外部系统；
2. 已确认需求的业务规则、数据口径或验收标准发生重大变化；
3. 实时点位数、采样频率、历史保留年限、并发量或视频路数超出基线；
4. 新增三维、地震资料格式、商业引擎或算法组件；
5. 新增国产化适配、等保/密评、容灾、多活或专项性能目标；
6. 甲方要求将现场设备、通信、云资源或第三方授权纳入乙方包干范围。

建议合同约定需求澄清阶段允许 **±15%** 的需求级调整；超出部分按变更评审结果调整费用和工期。

## 4. 用户角色与权限分析

### 4.1 用户角色

| 角色 | 主要职责 | 典型权限 |
|---|---|---|
| 平台管理员 | 维护平台基础配置、组织、角色、字典和系统参数 | 全局配置、用户授权、日志审计、运行监控 |
| 地质专业人员 | 维护井、层位、岩心、物性、图件、地震和测井资料 | 地质域数据维护、查询、分析和导出 |
| 工程技术人员 | 管理钻井、固井、井控、钻井液、压裂和试油数据 | 工程域录入、审核、查询和报表 |
| 生产管理人员 | 编制计划、调度生产、处理预警、查看曲线报表 | 生产域管理、监控和分析 |
| 现场/设备人员 | 维护设备、点位、采集状态和运行信息 | 设备与点位授权范围内维护、查看告警 |
| 数据管理员 | 维护标准、质量规则、数据字典和治理任务 | 标准管理、质量规则、问题处理和追踪 |
| 业务审核人 | 对业务数据、流程节点和发布内容进行审核 | 审核、退回、意见和结果确认 |
| 领导/驾驶舱用户 | 查看综合指标、专题、趋势、预警和下钻结果 | 授权范围内只读与分析 |
| 集成运维人员 | 维护接口、映射、转换规则和同步任务 | 接口配置、运行监控、重试和日志 |
| 安全审计人员 | 查看登录、权限、数据和操作审计 | 审计查询、导出和追责分析 |
| 外部系统/供应商账号 | 按接口授权交换数据 | API 调用、数据推送或查询，不具备后台管理权限 |

### 4.2 权限模型

平台采用“用户—组织—角色—数据范围—操作权限”组合模型：

- 支持按组织、区域、区块、井、项目、设备或资料类别控制数据范围；
- 支持菜单、页面、按钮、接口和导出权限控制；
- 支持查看、新增、修改、删除、审核、发布、导入、导出和配置等操作权限；
- 敏感数据默认最小化授权，导出应记录操作者、时间、条件和数据范围；
- 外部接口使用独立身份、密钥和权限，不直接复用普通用户账号；
- 所有权限变化、角色分配和高风险操作进入审计日志；
- 删除原则上采用逻辑删除或归档，涉及业务基线的数据不允许无痕物理删除。

## 5. 总体业务架构

### 5.1 分层架构

1. **访问层：** Web 管理端、驾驶舱端、移动/现场适配端（如纳入确认范围）；
2. **统一门户层：** 首页、一张图、工作台、菜单、消息和待办；
3. **业务应用层：** 地质、工程、生产、SCADA/物联网、公共管理；
4. **业务支撑层：** 组织权限、流程审批、字典、文档、报表、通知、审计和配置；
5. **数据服务层：** 主数据、关系数据、时序数据、文件/对象数据、分析数据和缓存；
6. **集成交换层：** 集团平台、供应商、SCADA、视频、GIS、统一认证和 AI 服务接口；
7. **基础设施层：** 计算、网络、数据库、存储、备份、安全和运维资源。

### 5.2 总体业务闭环

```text
数据来源/现场采集
    -> 接口接入与格式校验
    -> 数据映射、转换、标准化
    -> 质量校验与问题登记
    -> 业务域沉淀
    -> 查询、分析、报表、地图和驾驶舱展示
    -> 预警、审批、处置和反馈
    -> 审计、归档、统计和持续治理
```

## 6. 业务域需求分析

## 6.1 L01 油气藏地质管理（53 项）

### 6.1.1 业务目标

建立井、层位、储层、岩心、物性、录井、测井、地震、图件和三维资料的统一管理体系，支持地质资料从采集、整理、审核、分析到归档的全生命周期管理。

### 6.1.2 功能需求

**GEO-001 井与基础地质对象管理**

- 维护井基本信息、井号、井别、坐标、区块、构造位置和生命周期状态；
- 支持井与层位、井段、地层、储层、工程和生产对象关联；
- 支持批量导入、模板校验、重复检查和变更记录；
- 井号、区块、坐标系、单位和时间格式必须使用统一标准。

**GEO-002 岩心与取心资料管理**

- 管理取心井、取心段、岩心编号、深度、回收率、照片和描述信息；
- 支持岩心图像、文档和分析结果关联；
- 支持按井、层位、深度和样品条件检索；
- 重要资料支持审核、版本和归档。

**GEO-003 物性与实验分析管理**

- 管理孔隙度、渗透率、含油气性、饱和度等物性数据；
- 支持样品、实验条件、检测机构、结果值、单位和质量状态；
- 支持异常值、缺失值、重复样品和超范围规则校验；
- 支持实验报告与数据结果关联。

**GEO-004 地质图件管理**

- 管理平面图、剖面图、柱状图、构造图、储层图和解释成果；
- 支持图件版本、坐标系、比例尺、图层、来源和适用范围；
- 支持在线预览、下载授权和与井/区块/层位关联；
- 图件发布前应经过审核，历史版本可追溯。

**GEO-005 地震资料与 SEG-Y 管理**

- 管理地震资料目录、工区、测线、采集时间、坐标和处理版本；
- 支持 SEG-Y 文件或外部资料引用、元数据登记和权限控制；
- 支持与解释成果、井位、层位和图件关联；
- 专业解析、解释和商业组件能力以最终技术方案及授权为准。

**GEO-006 三维地质与空间数据**

- 支持三维模型、空间对象、井轨迹、地层和储层成果的关联展示；
- 支持空间查询、视图配置、对象定位和逐级下钻；
- 明确浏览器端支持格式、模型大小、并发和渲染性能；
- 三维引擎授权、格式转换和大文件处理能力需单独确认。

**GEO-007 录井与测井资料**

- 管理录井、测井曲线、解释成果、文件和结构化指标；
- 支持曲线按井、井段、测次、曲线类型和深度范围查询；
- 支持实时/历史曲线展示、单位转换、异常标识和版本管理；
- 支持与钻井工程、地质解释和生产对象关联。

**GEO-008 地质导向与综合分析**

- 管理地质导向目标、实际轨迹、层位判断和调整记录；
- 支持计划与实际对比、偏差提示和决策依据记录；
- 分析结果应保留计算参数、来源数据、操作者和生成时间。

**GEO-009 地质数据质量治理**

- 支持完整性、唯一性、一致性、范围、关联和时效性规则；
- 形成质量问题、责任人、整改要求、处理状态和复核记录；
- 支持质量评分、趋势统计和问题闭环。

### 6.1.3 主要输出

- 井/区块/层位综合档案；
- 地质资料目录和检索结果；
- 岩心、物性、录井、测井、地震和图件成果；
- 地质数据质量报告；
- 地质专题图件、曲线和分析报表。

## 6.2 L102 工程管理（60 项）

### 6.2.1 业务目标

覆盖井工程从计划、设计、施工、监督、质量控制到完工资料归档的全过程，形成钻井、固井、井控、钻井液、控压钻井、压裂和试油等专业协同能力。

### 6.2.2 功能需求

**ENG-001 工程项目与井工程基础管理**

- 管理工程项目、井、作业类型、承包商、计划周期、负责人和状态；
- 支持工程对象与地质、生产、设备和合同/供应商资料关联；
- 支持工程计划、变更、延期、暂停和完工归档。

**ENG-002 钻井设计与施工管理**

- 管理井身结构、钻具组合、井段计划、钻进参数和施工记录；
- 支持计划值、实际值、偏差、原因和处置措施；
- 支持日报、班报、施工阶段和关键节点记录；
- 对关键参数提供范围校验和异常提示。

**ENG-003 固井管理**

- 管理套管、固井设计、浆体参数、施工过程、候凝和质量评价；
- 支持设计与实际对比、附件资料和质量问题闭环；
- 支持固井报告、审核和归档。

**ENG-004 井控管理**

- 管理井控设备、试压、演练、风险、事件、处置和审核记录；
- 对高风险事项提供强提醒、责任人和处置时限；
- 支持井控资料、证据附件和审计追踪。

**ENG-005 钻井液管理**

- 管理钻井液体系、配方、材料、性能检测、密度、流变和现场记录；
- 支持按井段、时间和检测批次查询；
- 支持指标上下限、异常值和调整建议记录。

**ENG-006 控压钻井管理**

- 管理控压方案、设备、压力窗口、实时参数和调整记录；
- 支持计划曲线与实时曲线对比；
- 关键实时数据接入方式、采样频率和留存周期需专项确认。

**ENG-007 工程监督与质量管理**

- 管理监督任务、检查项、问题、整改、复验和评价；
- 支持承包商、作业队伍和工程阶段维度统计；
- 问题应关联责任人、证据、时限和关闭依据。

**ENG-008 压裂与试油管理**

- 管理作业设计、施工阶段、参数、材料、设备、测试和结果；
- 支持作业前审批、过程记录、结果评价和成果归档；
- 支持与生产、地质解释和产能评价关联。

**ENG-009 工程报表与综合查询**

- 提供工程日报、月报、统计报表、偏差分析和项目看板；
- 支持按井、区块、承包商、时间、工程类型和状态筛选；
- 报表口径、计算公式和导出格式应在需求确认阶段固定。

### 6.2.3 主要输出

- 工程项目和单井工程档案；
- 设计、施工、监督、质量和验收记录；
- 井控与高风险作业台账；
- 压裂/试油成果；
- 工程进度、质量和综合统计报表。

## 6.3 L03 生产管理（13 项）

围绕生产计划、调度、运行指标、预警、趋势和报表建立生产管理工作台，为管理人员提供统一的生产态势和问题处置入口。

### 6.3.2 功能需求

**PRO-001 生产计划管理**

- 管理年度、月度、周度和日计划；
- 支持目标、实际、完成率、偏差、原因和调整记录；

**PRO-002 生产调度管理**

- 管理生产任务、调度指令、执行反馈和异常事项；
- 支持按组织、区域、井、设备和时间查看调度状态；
- 支持待办、超期和升级提醒。

**PRO-003 生产预警管理**

- 基于指标阈值、趋势、质量码或业务规则生成预警；

**PRO-004 生产曲线与报表**

- 支持导出和与一张图、SCADA 数据关联。

**PRO-005 SCADA 数据存储使用**

- 接收经过标准化的 SCADA 数据并提供历史查询；
- 明确实时数据与业务统计数据的存储分层；

## 6.4 L04 SCADA 与物联网监控（7 项）

### 6.4.1 业务目标

建立平台侧的实时数据接入、点位管理、映射转换、质量识别、运行监控和历史存储能力，不默认替代现场采集设备和通信网络。

### 6.4.2 功能需求

**IOT-001 多协议/多来源接入**

- 支持按最终确认的协议接入 SCADA、物联网或供应商系统；
- 每种协议需明确连接方式、认证方式、数据格式和异常处理；
- 支持断线重连、失败重试、重复数据识别和接入日志。

**IOT-002 点位台账管理**

- 管理点位编码、名称、设备、位置、单位、采样频率、数据类型和状态；
- 支持点位启停、分组、版本和权限；
- 点位变更应保留历史映射关系。

**IOT-003 数据映射与转换规则**

- 支持源点位到平台标准点位的映射；
- 支持单位换算、枚举转换、比例换算、精度处理和缺省值规则；
- 转换规则发布需审批或至少保留版本及操作者。

**IOT-004 质量码与异常识别**

- 识别通信中断、越限、冻结、缺失、异常跳变和无效值；
- 质量码随数据保存并在曲线、告警和报表中可见；
- 质量问题可转为数据治理任务。

**IOT-005 实时监控与曲线**

- 提供点位实时值、最近值、历史曲线和状态；
- 支持按设备、井、区域、点位组和业务专题查看；
- 实时刷新频率和并发规模需依据实际点位量确认。

**IOT-006 接入运行监控**

- 监控接口连接、消息接收、解析、入库、延迟、失败和积压；
- 支持日志检索、失败重试、人工补偿和异常告警；
- 运行监控与业务数据问题应区分展示。

**IOT-007 数据归档与追溯**

- 支持实时数据转历史、归档、查询和按策略清理；
- 保留来源、接收时间、处理时间、质量码和转换版本；
- 归档策略需与数据库、时序库和对象存储容量方案一致。

### 6.4.3 关键前置条件

- 协议和供应商清单；
- 点位数量、采样周期、峰值吞吐和并发访问量；
- 历史数据规模与保留年限；
- 现场网络、VPN、专线和安全隔离方案；
- 数据时钟、时区、单位、质量码和补传机制。

**DASH-007 首页配置与发布**

- 支持管理员配置组件、指标、布局、专题、默认筛选和可见范围；
- 配置应支持草稿、预览、发布、回退和版本；
- 组件数据来源、刷新频率和失败状态应可查看。

## 8. 数据需求分析

### 8.1 数据分类

| 数据类别 | 示例 | 主要特征 |
|---|---|---|
| 主数据 | 井、区块、设备、组织、供应商 | 稳定、统一编码、跨域复用 |
| 业务数据 | 钻井、固井、压裂、生产计划 | 有流程、有责任人、可审核 |
| 实时数据 | SCADA 点位、压力、温度、设备状态 | 高频、时序、质量码、可补传 |
| 地质资料 | 岩心、物性、测井、地震、图件 | 大文件、专业格式、版本管理 |
| 公共数据 | 标准、字典、文档、需求、流程 | 跨域支撑、需治理 |
| 审计数据 | 登录、操作、接口、配置、导出 | 长期留存、防篡改、可追责 |

### 8.2 数据质量要求

- 关键主数据必须有唯一编码和有效期；
- 数值数据必须明确单位、精度、取值范围和缺失值语义；
- 时间数据必须统一时区、格式和采集/接收/处理时间；
- 空间数据必须明确坐标系、投影和转换责任；
- 实时数据必须保留质量码、来源、点位、采样时间和处理状态；
- 外部导入必须保存原始批次、导入人、导入时间、错误记录和处理结果；
- 业务数据修改应保留版本或变更审计；
- 指标和报表必须关联指标定义及数据来源。

### 8.3 历史数据初始化

甲方应提供：

1. 历史数据清单、数据字典和来源说明；
2. 可读的数据库、文件或接口数据；
3. 样例数据、完整数据量和质量问题说明；
4. 历史数据保留范围和初始化截止时间；
5. 数据脱敏、授权和安全传输要求。

乙方负责在约定范围内进行格式映射、导入脚本/工具、抽样核验和问题清单整理。源数据缺失、结构不稳定、质量严重不合格或需要人工专业判断的治理工作，应单独评估。

## 9. 接口与集成需求

### 9.1 外部集成对象

- 集团平台或上级业务平台；
- 统一认证与组织用户系统；
- 资源智管平台；
- SCADA/物联网平台和现场采集系统；
- 工程供应商或第三方业务系统；
- GIS、地图或三维服务；
- 视频平台；
- AI 服务或模型平台；
- 短信、邮件或其他通知平台。

### 9.2 接口通用要求

每个接口至少应确认：

- 接口提供方和责任人；
- 数据方向：推送、拉取、双向或文件交换；
- 协议：HTTP/API、WebSocket、MQ、FTP/SFTP、数据库交换或专用协议；
- 认证和加密方式；
- 请求/响应或文件格式；
- 编码、单位、时间、坐标和枚举映射；
- 超时、重试、幂等、补传和断点续传机制；
- 数据量、频率、峰值和 SLA；
- 错误码、日志、告警和人工补偿；
- 测试环境、样例数据、联调窗口和上线审批。

### 9.3 接口验收原则

- 以接口联调记录、样例数据和双方确认的字段映射表为依据；
- 接口失败不得在平台显示为成功；
- 重复推送不得造成业务数据重复；
- 关键数据应可追踪原始来源和处理结果；
- 外部系统未按时提供接口或环境时，相关工期应顺延，不能将对方系统问题认定为平台功能缺陷。

## 10. 非功能需求

### 10.1 性能

最终指标必须以容量评估和甲方确认值为准，至少应明确：

- 用户总数、活跃用户数、并发用户数；
- 常规查询、复杂报表、地图和实时曲线的响应目标；
- SCADA 点位数、采样周期、峰值吞吐、端到端延迟；
- 文件上传下载大小和并发；
- 历史数据量、增长量和保留周期；
- 一张图组件数量、刷新频率和下钻响应目标。

在未完成真实容量和生产环境验证前，不承诺固定的生产 P95、峰值吞吐和高可用指标。建议常规业务请求以 P95 小于 2 秒作为初步讨论目标，但不含外部系统调用、超大文件处理和复杂三维渲染。

### 10.2 可用性与可靠性

- 服务异常应有明确错误提示和日志；
- 接口、采集和异步任务支持失败重试或人工补偿；
- 关键写操作采用事务，避免部分成功；
- 重要业务支持草稿、版本、归档和恢复；
- 生产高可用、容灾、备份恢复目标需结合基础设施方案另行确认。

### 10.3 安全

- 采用统一认证、会话控制、最小权限和数据范围控制；
- 重要接口进行身份、权限、参数和数据归属校验；
- 防止越权访问、批量枚举、注入、路径穿越和未授权下载；
- 敏感数据传输和存储应按甲方安全制度加密或脱敏；
- 关键操作记录审计，审计日志不得由普通业务用户修改；
- 等保、密评、工控安全和信创适配以甲方安全等级及专项合同为准。

### 10.4 可维护性

- 业务模块、公共底座和集成适配应分层设计；
- 配置、字典、规则和指标尽可能可维护，避免硬编码；
- 提供部署说明、运维手册、接口文档、数据字典和常见问题手册；

## 13. 验收分析与验收建议

### 13.1 验收层级

建议采用“功能点—业务域—平台整体”三级验收：

1. **功能点验收：** 以原始 Excel 逐项编号为准，确认功能、权限、输入、输出和异常场景；
2. **业务域验收：** 按 L01、L102、L03、L04、L05、L06 分域进行端到端业务流程验收；
3. **平台整体验收：** 验证统一认证、权限、流程、接口、审计、部署、培训和试运行。

### 13.2 功能验收通用条件

每项功能至少应满足：

- 正常场景可操作；
- 必填、格式、范围和关联校验有效；
- 无权限用户不可操作或不可见；
- 审核、退回、修改、归档和版本场景符合规则；
- 成功和失败状态提示准确；
- 关键操作可审计；
- 业务结果可查询、可追溯或可导出；
- 与关联业务对象的数据一致。

### 13.3 专项验收条件

- **实时接入：** 使用双方确认的协议、样例点位和测试数据验证接收、解析、映射、质量码、入库、告警和断线恢复；
- **GIS/三维：** 使用甲方确认的坐标、图层、模型和数据量验证展示、定位、下钻和权限；
- **SEG-Y：** 以最终确定的解析/预览范围和授权组件验收，不默认承诺专业解释全能力；
- **历史数据：** 按双方确认的数据批次、字段映射、抽检比例和错误处理报告验收；
- **接口：** 按接口清单、字段映射、异常码、重试、幂等和日志验收；
- **安全：** 按甲方确认的安全要求和专项测评范围验收，不将未采购的第三方安全产品视为软件缺陷；
- **性能：** 仅在双方确认的生产同构环境、容量基线和测试脚本下验收。

# 19. 技术方案要求（需求阶段边界）

本章提出可用于方案设计、招标评审和实施估算的技术要求，不替代后续《总体技术方案》《详细设计说明书》和《数据库设计说明书》。技术路线应在需求澄清和容量评估后冻结。

## 19.1 推荐总体技术架构

建议采用前后端分离、分层解耦和适配器可替换的架构：

```text
Web/移动/驾驶舱
      -> API 网关与统一认证
      -> 业务应用服务（地质/工程/生产/物联/一张图/数据治理）
      -> 公共服务（权限/流程/消息/文件/报表/审计）
      -> 数据服务（关系库/时序库/对象存储/缓存/检索）
      -> 集成适配（集团/供应商/SCADA/GIS/视频/AI）
```

建议技术选型方向：

- 前端：响应式 Web 管理端与驾驶舱，必要时提供移动/现场适配；
- 后端：模块化服务或分层单体，优先保证事务一致性和运维简洁；
- 接口：REST/JSON 为主，实时数据按场景采用 WebSocket、消息队列或专用协议；
- 数据：关系型数据库承载主数据和业务事务，时序数据库承载高频采集数据，对象存储承载大文件；
- 异步任务：用于批量导入、报表生成、文件处理、数据同步和补偿；
- 认证授权：统一认证、RBAC/数据权限、接口鉴权和审计；
- 部署：支持甲方机房或云环境，具体操作系统、中间件和数据库以信创及安全要求为准。

## 19.2 模块化要求

各业务域应具备清晰边界：

1. 地质、工程、生产和物联模块不得通过直接修改对方表结构实现耦合；
2. 主数据、字典、组织、权限、流程、消息和审计作为公共能力统一提供；
3. 外部系统通过接口适配层接入，不将供应商特定格式扩散到核心业务模型；
4. 实时采集与业务事务解耦，接入中断不得阻塞常规业务查询；
5. 报表和驾驶舱引用统一指标服务或指标定义，避免同名指标多套口径；
6. 专业解析组件、地图引擎和对象存储通过可替换接口封装。

## 19.3 数据架构要求

- 建立主数据、业务数据、实时数据、文件数据和审计数据分层；
- 关系数据与时序数据通过井、设备、点位、组织和时间等统一标识关联；
- 大文件不建议直接存入业务数据库，应保存元数据、权限、版本、校验摘要和存储定位；
- 重要数据写入应具备幂等、事务或可补偿机制；
- 数据库迁移脚本、初始化脚本和字典数据应纳入版本管理；
- 提供数据备份、恢复、归档、清理和留存策略；
- 数据模型应支持未来从单体部署向服务化或国产化环境迁移，但本期不以复杂微服务为强制前提。

## 19.4 接口与集成架构要求

- 统一接口目录、版本、认证、错误码、日志和限流策略；
- 每个外部接口提供字段映射、时序图、异常处理和联调记录；
- 同步接口设置超时和重试，异步接口设置消息状态、幂等键和补偿机制；
- 接口数据必须区分业务发生时间、采集时间、接收时间和入库时间；
- 对 SCADA 和物联网数据提供接入缓冲、断线重连、积压监控和失败补偿；
- 外部系统不可用时，平台应保持可解释的降级状态，不显示虚假成功。

## 19.5 应用与交互要求

- 页面按角色展示菜单、待办、指标和数据范围；
- 表单支持草稿、校验、保存、提交、退回、修订和版本；
- 列表支持分页、条件查询、排序、导出权限和查询状态提示；
- 驾驶舱支持大屏、普通浏览器和不同分辨率适配；
- 实时页面展示数据时间、刷新时间、质量码和延迟状态；
- 错误提示应说明可操作的处理方式，不直接暴露内部堆栈或敏感信息。

## 19.6 部署与运维要求

- 提供开发、测试、预生产和生产环境的配置隔离；
- 配置、密钥和证书不得硬编码在代码或文档中；
- 提供健康检查、日志、指标、告警和运行状态查看；
- 发布支持版本、回退和变更记录；
- 明确数据库、时序库、对象存储、消息组件和外部系统的运维责任；
- 运维手册应包含启动停止、备份恢复、日志定位、接口重试和常见故障处理。

# 22. 质保、运维与服务等级

## 22.1 质保期服务

建议质保期 12 个月，自终验合格之日起计算。质保范围包括合同范围内软件缺陷修复、部署问题协助、关键接口问题定位和使用答疑；不包括新增需求、外部系统变更、设备故障、网络故障、第三方组件授权失效和未经授权的环境改造。

## 22.2 运维服务内容

- 应用运行监控和故障定位；
- 数据库、时序库、文件存储和日志容量检查；
- 接口、采集、消息积压和失败任务检查；
- 账号、权限、字典和配置维护；
- 数据质量问题协助分析；
- 版本发布、补丁和变更管理；
- 定期运行报告、问题统计和优化建议。

## 22.3 建议服务等级

| 事件等级 | 示例 | 建议响应 | 建议处理 |
|---|---|---:|---:|
| P1 阻断 | 平台整体不可用、关键数据写入失败 | 30 分钟 | 4 小时内给出恢复方案，持续跟进 |

# 23. 项目验收与付款关联

建议每个付款节点均绑定可核验成果：

1. **启动款 20%：** 合同生效、项目组成立、计划和资料清单确认；
2. **设计款 20%：** 需求基线、原型、总体方案和接口/数据清单确认；
3. **核心上线款 25%：** 公共底座及约定第一批业务上线，测试报告通过；
4. **开发完成款 20%：** 约定功能开发完成、系统测试通过并进入试运行；
5. **初验款 10%：** 试运行达到约定周期，主要缺陷关闭，初验通过；
6. **终验/质保金 5%：** 终验材料齐全、遗留事项有明确处理计划，按合同释放。

不建议使用“所有外部系统、现场设备、商业授权和安全测评全部完成”作为乙方软件付款的无条件前置，除非这些内容被明确纳入乙方合同范围并已具备对应环境。

# 25. 统稿结论

本项目应按“中大型油气田数字化平台”管理，不应按普通管理后台或单纯 CRUD 项目估价。完整项目要素建议固化为：

- **范围：** 178 项一期功能，六大业务域 + 公共底座 + 集成初始化；
- **技术：** 前后端分离/分层架构，关系数据 + 时序数据 + 文件对象分层，统一认证权限、接口适配、审计和运维；
- **工期：** 12—15 个月，分两批或三批上线；
- **工作量：** 约 2,360 人日；
- **软件实施报价：** 建议 598 万元含税；
- **外部预算：** 基础设施及授权暂估 80—180 万元，质保后运维 72—90 万元/年；
- **组织：** 平均 7—9 人、峰值 12—16 人，甲方需配置业务专家、数据负责人、接口负责人和验收组；
- **验收：** 功能点、业务域、平台整体三级验收，并对实时、GIS/三维、专业资料、接口、数据初始化、安全和性能单独验收；
- **关键前提：** 原始 Excel 逐项确认、接口和数据按时提供、点位与容量明确、商业组件和安全责任边界清晰；
- **商务原则：** 需求基线 + 变更机制 + 责任矩阵 + 需求追踪矩阵共同构成合同执行基础。
