## 3. 软件落地情况分析

### 3.1 服务器与部署架构 ✅

| 项 | 现状 |
|----|------|
| 前端 | Cloudflare Pages（`wxx-agent`），正式入口 `https://www.wxx-agent.online`（边缘、免 ICP 直连大陆） |
| 后端 | 腾讯云 Lighthouse（`129.211.223.113`，Ubuntu 22.04）Go 二进制 systemd 常驻 |
| Web 服务器 | Caddy 反向代理 + 自动 HTTPS |
| 数据库 | 服务器本地 SQLite `/opt/wxx/data/wxx.db`（含 FTS5），~58µs 本地延迟 |
| 鉴权 | CF Functions JWT 鉴权 → 后端 8080 |
| 代理链路 | 用户→CF Pages→CF Functions→Go(8080)→SQLite |

**评估**：架构稳定、环节清晰、有自动续期 HTTPS；无 Serverless 冷启动/超时风险，LLM 长请求不受截断。

### 3.2 数据同步 ✅

| 项 | 现状 | 结论 |
|----|------|------|
| 多人写并发 | 单机 SQLite 单写者，无多实例冲突 | ✅ 本方案最优 |
| 后台数据 | 数据持久化于 SQLite | ✅ |
| 同步工具 | `server/cmd/sync-db/main.go`（`app.SyncDB`）+ `sync-db.exe` | ✅ 具存在 |
| 实时数据 | 数字孪生、情感、打卡、问答均实时库 | ✅ |
| 备份机制 | 文档 §备份 提供 cron 每日 `.backup` + 14 天轮转 | ⚠️ 需确认服务器已实际启用 |

### 3.3 Web 与 APK 一致性 ✅

- 同一套 Flutter 代码构建 Web + Android，`MainShell` 响应式（>900px 桌面 NavigationRail / 移动 NavigationBar）。
- 语音 iOS = Web（MediaRecorder）/ Android（record）条件编译，功能对齐（文档表"各端能力差异"均 ✅）。
- APK 经 GitHub Release 分发（`weixiaoxin.apk` 固定 `latest/download` 入口），版本 `ReleaseConfig.version=0.0.16`、build 16。
- **一致性确认**：两端同源同功能；唯一差异为语音底层实现，但能力对齐。

### 3.4 安全与保密

| 控制项 | 现状 | 结论 |
|--------|------|------|
| 认证 | JWT（`JWT_SECRET`≥32位，经 /user/capabilities 下发能力） | ✅ |
| 授权 | RBAC 104 capability，`RequireCapability` 门控；前端仅隐藏、后端强制 | ✅ |
| 密码 | bcrypt 哈希，不存明文；导入可设统一初始或=学号 | ✅ |
| 游客注册 | 默认关闭（3.9/4.15 `ENABLE_GUEST_REGISTER` 关） | ✅ |
| 隐私同意 | 首次启动隐私弹窗（ConsentPage）+ `firstLaunchDone` 门控 | ✅ |
| PII 脱敏 | 学号/手机号/身份证经脱敏中间件后入 LLM | ✅ |
| SQL 注入 | FTS5 经 `escapeFTS`；排序字段白名单 | ✅ |
| 校验消息 | 部分 handler 仍含 `err.Error()`（graduation/model_config/process/session/study_plan/voice 等） | ⚠️ 待清 |
| 密钥管理 | 密钥存 `/etc/wxx/env`（服务器本地，不入库） | ✅ |

**结论**：整体安全设计达标；发布前建议清零 §3.4 / §8 的 `err.Error()` 泄露告警项（非阻断，2h 工作量）。

### 3.5 用户粘性

> 学生端「**七层粘性架构**」已在代码落地：每日陪伴（速览/日记/打卡）→ 学情洞察（课程学情/周报）→ 成长规划（数字孪生/新生规划/路径）→ 能力发展（竞赛/学伴/面试/简历）→ 校园生活（情报站/日程/生活）→ 社区互动（问答/热点/私聊/排行）→ 成长激励（积分/成就/打卡奖励/性格洞察）。
>
> 高频钩子：**每天首次打开**今日速览 → 每日打卡 → 学习日记，具备「让学生每天打开」的机制。

**评估**：粘性架构完整落地，粘性机制（连续打卡/成就/排行）形成正向循环。

### 3.6 软件特色与亮点

1. **AI 原生**：每日速览/学习日记/性格洞察/数字孪生解读，均由大模型生成，非模板。

4. **报到地图 + 万点点位**：管理员拖拽校正坐标，一键落位，贴合线下报到场景。
5. **社区共创**：问答广场 AI 先答 + 人工补充 + 排行榜激励。

## 4. 发布流程

### 4.1 发布前置

1. **整改**：清零 `err.Error()` 泄露（§3.4 清单，约 2h）；确认服务器已启用每日备份 cron；
2. **版本号**：`make deploy-release` 自动递增 patch + build（当前 0.0.16+16 → 0.0.17+17），同步 `release_config.dart`、`release.json`、APK 下载清单。
3. **发布口径**：明确 C0（真实可用）/ C1（演示数据）/ C2（数据源依赖）三档，避免「有页面=已实现」误判。

### 4.2 后端发布

```bash
# 在服务器 /opt/wxx：（或本机编译后 scp 上传）
export GOPROXY=https://goproxy.cn,direct
go build -tags fts5 -o /opt/wxx/wxx-server ./server/cmd/server

# 备份
sqlite3 /opt/wxx/data/wxx.db ".backup '/opt/wxx/backup/wxx-pre-release.db'"

# 迁移 + 重启
./wxx-server migrate && systemctl restart wxx

# 验证
curl -s http://localhost:8080/api/v1/health   # status=healthy, fts5=ok, sqlite=ok
```

### 4.3 前端发布

```bash
cd frontend
make deploy-web        # 构建 web + 同步 functions + wrangler pages deploy
# 发布验证
curl -s https://www.wxx-agent.online/ | grep -o "蔚小芯"
curl -s https://www.wxx-agent.online/api/health
```

### 4.4 发布后验收

1. Web 入口、APK 下载（GitHub Release）均可用；
2. 至少一个学生、一个辅导员、一个管理员账号登录冒烟（首页/问答/数字孪生/安全）;
3. `make deploy-release` 产物校验 `蔚小芯-v版本号.apk` + `release.json`；
4. 提交 Git 并打 tag（`git tag v0.0.X`）触发 GitHub Actions 出 Release。

## 5. 新生用户操作指南

### 5.1 首次使用（登录 X 分钟上手）

1. **打开**：浏览器访问 `https://www.wxx-agent.online`，或手机扫首页二维码安装 `蔚小芯.apk`。
2. **首次**：出现隐私政策弹窗 → 点「同意」方可使用。
3. **登录**：输入管理员分配的 **学号 + 初始密码**（默认初始密码=学号，或导入时统一密码）。
4. **改密**：登录后到「我的 → 用户管理 / 账号设置」修改密码（登录必须同时提交账号+密码）。
5. **完善**：到「我的」完善头像、入学年份（影响年级主题）等。

### 5.2 在校日常（每日/周期）

| 场景 | 操作 |
|------|------|
| 每日速览 | 首页 → AI 今日速览（课程/事项/活动/指南） |
| 每日打卡 | 我的 → AI 学习日记 → 打卡；或每日打卡页 |
| 提问 | 首页底部「对话」→ 语音（🎤）或文字向 AI 提问 |
| 视频 | 首页「办事」→ 报到流程 / 日常办事（地点、联系人、材料） |
| 数字孪生 | 首页 FAB / 我的 → 数字孪生（五维画像+数字人显示） |

### 5.3 报到（新生）

报到地图（首页/办事→报到）逐节点：登录 → 查看报到点列表 → 按地图节点到现场办理 → 每节点标记/推进进度。

### 5.4 离校/就业（大四）

毕业题、就业（岗位/政策/面试）、简历、模拟面试、思想档案/入党。

### 5.5 安全提示

- 请勿泄露账号密码；会复位密码联系辅导员/管理员。
- 初始密码须及时修改。
