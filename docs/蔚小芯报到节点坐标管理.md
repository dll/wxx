# 蔚小芯报到节点坐标管理

> 管理员可在校园地图上拖拽校正报到节点坐标，或通过流程管理面板对报到步骤进行全生命周期 CRUD 管理。其它角色只读。

## 功能概述

| 能力 | 管理员（sys/school/college_admin） | 其它角色 |
|------|:---:|:---:|
| 查看报到节点 | ✅ | ✅ |
| 拖拽校正坐标 | ✅ | ❌ |
| 新建/编辑/删除步骤 | ✅ | ❌ |
| 提交审核 / 发布 | ✅ | ❌ |
| 流程管理面板入口 | ✅ | ❌ |

## 拖拽校正坐标

管理员登录后，校园地图顶部出现「管理」按钮（PopupMenuButton，整合「编辑节点」与「流程管理」入口）：

1. 点击「管理」→「编辑节点（拖拽校正）」进入编辑模式，顶部提示「拖动标注即可校正位置，松手自动保存」
2. **直接拖拽**地图上的报到标注到实地位置（无需按住 Ctrl 键，鼠标/触摸均可）
3. 松手后自动调用 `PATCH /admin/campus/steps/:id/coords` 保存新坐标
4. 保存成功弹出 SnackBar「节点坐标已保存」，全员立即可见

该接口不受 `draft` 状态限制，已发布步骤也可直接微调坐标，不走审核流程。坐标需在中国范围内（纬度 3-54，经度 73-136），否则拒绝保存。

### 拖拽实现要点

- **全局事件管理**：document 只注册一次 `mousemove/mouseup/touchmove/touchend/touchcancel`，避免每个标注各自注册导致事件冲突（表现为"第1个能拖、后面拖不动"）。
- **移动阈值**：`_DRAG_THRESHOLD=5px`，鼠标/手指移动小于 5px 视为点击而非拖动，避免点击标注误触发 `marker_moved` → Flutter `setState` → `refresh` → 标注重建链路打断后续拖拽。
- **触摸支持**：`touchstart/touchmove/touchend` 事件，移动端可直接触摸拖拽。
- **pointer-events**：iframe 与 host div 显式设置 `pointer-events:auto`，穿透 Flutter Web CanvasKit 平台视图指针拦截层。
- **临时禁用地图拖拽**：`mousedown/touchstart` 时 `disableDragging()`，`mouseup/touchend` 时 `enableDragging()`，防止地图与标注同时拖拽。

## 流程管理面板（CRUD）

管理员点击「流程管理」按钮，弹出底部面板，支持完整的工作流：

```
新建(draft) → 编辑(draft) → 提交审核(pending_review) → 发布(published)
   ↑                                                            │
   └──────────── 删除(仅 draft) ←──────────────────────────────┘
```

| 操作 | 允许的状态 | 接口 |
|------|------------|------|
| 新建 | — | `POST /admin/campus/steps` |
| 编辑 | draft | `PUT /admin/campus/steps/:id` |
| 删除 | draft | `DELETE /admin/campus/steps/:id` |
| 提交审核 | draft → pending_review | `POST /admin/campus/steps/:id/submit` |
| 发布 | pending_review → published | `POST /admin/campus/steps/:id/publish` |
| 校正坐标 | 任意状态 | `PATCH /admin/campus/steps/:id/coords` |
| 强制更新内容 | 任意状态（已发布也可改） | `PUT /admin/campus/steps/:id/force` |
| 强制删除 | 任意状态（已发布也可删） | `DELETE /admin/campus/steps/:id/force` |

面板关闭后自动刷新地图标注，确保与后端数据一致。

> **强制更新/删除**：管理员可修改或删除任意状态的步骤（包括已发布），用于现场快速修正。draft 状态走普通接口（保留审核流程语义），其它状态走 force 接口。

## 权限控制

- **后端**：所有 `/admin/campus/steps/*` 路由要求 `CollegeUserRead` 能力，发布操作要求 `CollegeDataAnalysis` 能力。能力继承链：`sys_admin` → `school_admin` → `college_admin`。
- **前端**：`campus_map_page.dart` 的 `_canEditNodes` 检查 `Storage.role`，仅 `sys_admin`/`school_admin`/`college_admin` 显示编辑按钮和流程管理入口。
- **公开接口**：`GET /campus/steps` 无需登录，所有角色可查看已发布步骤。

## 坐标数据来源

两校区报到节点坐标采用 OpenStreetMap 权威数据（迁移 `050_fix_campus_step_coords.sql`）：

| 校区 | OSM way ID | 中心坐标 | 四至范围 |
|------|------------|----------|----------|
| 会峰校区 | 734826227 | 32.2743, 118.3055 | N32.2803 S32.2688 E118.3120 W118.2986 |
| 琅琊校区 | 734826234 | 32.2943, 118.2978 | N32.2962 S32.2913 E118.3005 W118.2931 |

坐标系统为 WGS-84，由前端 BMapGL iframe 内部完成 WGS-84 → BD-09 转换。

## 离线回退

前端 `campus_map_page.dart` 内置两校区报到步骤硬编码常量（`_huifengSteps`/`_langyaSteps`）。后端不可用时自动回退到本地常量，保证离线场景下地图仍可使用。管理员拖拽保存时若后端无对应记录（本地回退模式），仅本地保存并提示。
