# 任务方案 — 系统整合与测试

## 背景与目标

处理 6 项任务：学院改名、门户信息导入、通知推送、25 级学生导入测试、多格式文档 RAG 上传、全功能验证。

## 范围

| 编号 | 任务 | 范围（做 / 不做） | 工作量 |
|------|------|-------------------|--------|
| 1 | 学院改名「信息学院」→「计算机科学与工程学院（网络空间安全学院）」 | 数据库种子、Go 代码、Flutter 前端、Web manifest、docs 全部替换 | 小 |
| 2 | 导入滁州学院各子系统（学工/泛雅/教务等）入口信息到知识库 | 添加一批知识资源（FAQ 类型），覆盖子系统访问方式 | 中 |
| 3 | 蔚小芯发送通知同时推送到 QQ/微信群 | 新建 notification 表 + 管理 API + 前端通知界面；QQ/微信推送用 webhook 机制 | 大 |
| 4 | 导入 25 级测试学生 | 生成测试数据 → 通过 `POST /admin/users/import` 导入 | 小 |
| 5 | 支持 PDF/DOCX/XLSX/CSV/TXT/图片/视频上传创建 RAG 知识库 | 新增文件上传端点 + 文本提取 + 知识入库；视频暂提取字幕 | 大 |
| 6 | 检查所有用户 AI 功能及 API Key 有效性 | 运行测试 + 调用各 LLM API 验证 | 中 |

## 技术要点

- **改名**：全项目文本替换 + 迁移脚本（`030_rename_college.sql`）更新种子数据
- **门户知识**：在 `server/data/seed/` 新增 `portals.ndjson`，含各子系统 URL、登录方式、功能说明
- **通知推送**：新建表 `notifications`；后端 `POST /api/v1/notifications` + 前端通知管理页；QQ webhook 用 go-resty 调用群机器人 API；微信推送到企微 webhook
- **25 级导入**：脚本生成 50 条模拟学生数据 → 调用 API 导入
- **多格式上传**：新增 `POST /api/v1/kb/upload`（multipart）；用 Go 库提取文本（`unipdf`/`unioffice`/`excelize`）；图片 OCR 调用智谱 4V；视频暂提取文件名/描述元数据
- **Key 检查**：逐个调用 LLM API health/chat 端点验证

## 步骤拆分

1. **Plan** → 用户确认本方案
2. 学院改名（全局替换 + 迁移脚本）
3. 门户知识导入（新增 portals.ndjson + 迁移加载）
4. 通知推送（表 + 后端 + webhook + 前端）
5. 25 级测试学生导入（生成数据 + 调用 API）
6. 多格式 RAG 上传（文件端点 + 文本提取 + 入库）
7. 全功能验证（Key 检查 + 功能冒烟）
8. Git 提交

## 验收标准

- 所有界面「信息学院」改为「计算机科学与工程学院」
- AI 对话能准确回答各子系统访问方式
- 通知可创建并推送到指定 webhook
- 25 级学生可正常登录并使用学生功能
- 上传 PDF/DOCX/XLSX 后可检索到其中内容
- 所有 API Key 返回有效响应

## 回滚与检查点

- 每个步骤独立 Git commit，可逐个 revert
- 改名步骤前备份数据库
- 通知表可安全回退（DROP TABLE IF EXISTS）
