## ✅ 全面审核修复（commit 6922b6b，main 已推 origin）

按 wxx-code-review 技能清单（架构/安全/知识管道/质量）对项目做了全面审核，修复 3 类**安全/越权**问题 + 回归测试：

### ① college_admin 跨学院数据泄漏（阻断级）
- **根因演化**：学生导入 owner_id=学院名 → 旧实现 college_admin 强制 owner_id 过滤致 600+ 学生不可见（前一轮放开 owner_id 又造成跨学院泄漏）。
- **修复**（`admin_handler.go`）：按操作者自身 college 定位归属——`resolveOperatorCollege(userID)` 取账号 college 字段（空则回退 owner_id）；`ListUsers` 用 owner_id=操作者学院、`ListUsersAdvanced` 强制 `college=操作者学院`（college 列为准，前端传其他一律覆盖）、`GetUserDict` 字典下拉限本院。
- **注意**：120001 需将账号 `college`/`owner_id` 配为其本职学院，否则本院列表可能仍为空（仅限本院，不泄漏）。

### ② 多角色 stale-roles 越权（阻断级）
- **根因**：旧 JWT 仅带登录时刻 roles；`ReplaceRoles` 仅主角色变化才 bump token_version。被移除角色的旧令牌仍携旧 roles，且 `EnsureUserExists`/`UpsertFromContext` 不覆盖 `Roles`（只覆盖 Role/Scope/Status），可经 `HasAnyRole` 并集判定行使已撤销能力。
- **修复**（`user_repo.go` UpsertFromContext）：每次请求以数据库 `GetRoles` 权威覆盖 `userCtx.Roles`，DB 成为角色唯一权威。`EnsureUserExists` 挂载于全部 `secured` 路由（routes.go:140），全局生效。
- **回归**：`TestUserRepo_UpsertFromContext_RefreshStaleRoles`。

### ③ 学生活动统计未按学院隔离（警告级）
- **根因**：`user_activity_stats` 全校聚合，college_admin 可获全校注册/登录/打卡。
- **修复**：`GetUserActivityStats(scopeType, scopeID)` 新增范围；handler `resolveScope` 按操作者 role 判范围（college_admin 按 users.college 过滤注册/登录/打卡/近7日趋势）。全局口径无 JOIN（保留原行为），college 口径 JOIN users。
- **回归**：`TestUserActivityStats_CollegeScope`。

### 核查无问题项（存档）
- SQL 注入：全部 `?` 参数化 + 列名白名单（user_repo/graduation_repo/student_features 的 fmt.Sprintf 拼接均为白名单后固定片段）。
- 硬编码密钥：无（JWT_SECRET 强制 ≥32 位且拒绝默认值；测试 key 除外）。
- JWT：签名算法仅 HMAC、校验过期/iss/nbf、状态拦截 pending/rejected/disabled、token_version 吊销经 EnsureUserExists。
- SSRF：门户代理 allowlist（仅 my0.chzu.edu.cn/chzu.edu.cn 及子域，剥端口）。
- 审计：AuditLog 中间件全局异步记录 request 级（method/path/user/status/trace_id）。
- privacy：SanitizePrivate 按角色脱敏。
