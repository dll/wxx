# knowledge/wiki — 项目组内部 LLM Wiki 运营流程

> 定位：**团队内部知识沉淀**，不是产品线上知识库。见 `knowledge/README.md` 与
> Context Engine 的边界约定。本目录仅存**已提炼的结论**，原始素材放 `knowledge/raw/`。

## 什么是 wiki 条目

一条 wiki = 一个「高频问题 / 关键决策 / 踩坑记录 → 标准结论 + 引用源」。

它是 Context Engine 高置信锚点的**人工沉淀来源**：当某个答案被反复确认正确后，
应沉淀为 wiki 条目，再按发布流程反哺线上知识库。

## 条目生命周期

```
draft（起草） → reviewed（复核） → stable（定稿） → archived（归档）
```

- `draft`：草稿，结论尚未被复核，仅本人维护。
- `reviewed`：已被至少一人复核，交叉引用与来源齐备。
- `stable`：被两个以上独立来源验证 / 连续使用无异议；可考虑反哺线上。
- `archived`：结论已过时或并入其它条目，保留留痕但不参与检索。

**front-matter 字段**（模板见 `_template.md`）：

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | ✅ | 一句话主题（2~30 字） |
| `status` | ✅ | 上述生命周期状态 |
| `created` | ✅ | 创建日期 `YYYY-MM-DD` |
| `last_reviewed` | ✅ | 最近复核日期 |
| `owner` | ✅ | 维护人（学号/用户名） |
| `tags` | ✅ | 检索标签，逗号分隔 |
| `sources` | ✅ | 引用源：`docs/`、`specs/`、线上资源 ID、PR/commit |

## 命名与检索

- 文件名：`YYYY-MM-DD-短横线主题.md`（如 `2026-08-02-fts-tags-bm25.md`）。
- 一条条目 = 一个主题，避免把多个结论堆进同一文件。
- 交叉引用：用相对路径链接其它条目；引用正式文档用其在仓库中的相对路径。

## 沉淀流程（从问题到条目）

1. **识别高频问题 / 关键决策**：对话/评审中被反复问到，或做出了影响后续开发的取舍。
2. **起草**：用 `_template.md` 新建条目，标注 `status: draft`，尽量给出可验证的结论。
3. **复核**：至少一名成员检查结论、补充 `sources`，改为 `reviewed`。
4. **定稿 / 反哺**：结论稳定后，若面向师生，走 `docs/knowledge-governance.md`
   与 `specs/export-package.md` 的治理流程发布到线上知识库；条目状态置 `stable`。
5. **维护**：与 `docs/`、`specs/` 保持同步，避免漂移；定期清理 `archived` 条目。

## 与线上知识库的边界

- `knowledge/wiki/` **不自动**等于对外发布内容；对外发布须走审核与版本流程。
- 线上 `kb_resources` 的元数据（标题/摘要/标签）质量低时，可引导管理员
  将稳定答案沉淀为 wiki 条目，再作为结构化高质量数据反哺（人工把关）。
- 文档精修（`docs/knowledge-refine.md`）是「提升现有资源元数据」；
  wiki 是「把团队结论沉淀为可复用条目」，二者互补。
